# 多初值兜底正式接入修改记录

日期：2026-07-24

## 修改目标

把已验证过的多初值跨帧思路整理成正式 C++ 算法模块，并接到现有分层重定位链路的最后一级。该能力默认关闭，不改变当前正式运行行为；打开后也不拥有 TF 发布权。

## 正式流程

```text
默认召回和时序/轨迹门控
  -> 精度层实际尝试后仍拒绝，或精度层数据库不可用
  -> 同一失败帧精配候选按来源聚类
  -> 每个seed建立独立map->odom轨迹
  -> odom传播 + 首帧局部SE(2)搜索 + 连续细GICP
  -> rolling12单轨迹质量门控
  -> 至少两条同来源轨迹一致
  -> accepted_multi_seed
  -> RO trusted commit
  -> Bridge 唯一发布 map->odom
```

多初值层不会在默认层正常成功时运行，也不会因超时降低接受门槛。批次超时、候选歧义、支持帧不足或轨迹一致性不足都会安全拒绝。

## 代码修改

- `multi_seed_verifier.hpp/.cpp`
  - 对同一帧精配后的 BBS/SOLiD 候选按来源和 `0.35m/10deg` 聚类。
  - 每簇最多保留三条独立轨迹，使用各自 `map->odom` 和当前 odom 形成预测。
  - 首次跟踪执行 `+/-0.5m/+/-20deg` 局部 SE(2) 搜索、NMS 和 top4 粗 GICP。
  - 后续使用 `0.10m` 点云、`0.30m` 对应距离和 50 次迭代做连续细 GICP。
  - rolling12 至少九帧有效，并检查修正量、fitness、RMSE 和 `map->odom` spread。
  - 至少两条同来源、同初始簇轨迹在 `0.08m/2deg` 内一致才输出候选。
- `refiner.hpp/.cpp`
  - 增加每线程独立的 `RefineSession`。
  - 同一线程的一批候选共享地图、scan 和 PCL 后端上下文。
  - 保留原有单候选和 top-K 接口。
- `global_relocalization_node.cpp`
  - 多初值任务使用后台 `future` 执行，ROS 主线程定时领取结果。
  - 同时最多一个正式批次。
  - attempt、地图切换和 cancel 使用 generation 隔离旧结果。
  - 最终候选继续经过历史 scan overlap 门控。
  - 输出状态增加 `multi_seed_*` 审计字段。
- `config.hpp`、`config_loader.cpp` 和两份 YAML
  - 增加多初值配置结构和参数加载。
  - 正式、验证模板均保持 `enable_multi_seed_recovery: false`。

## 安全边界

1. 算法节点仍只发布候选 PoseStamped 和状态，不发布 TF。
2. `map->odom` 仍只能由 `prior_map_odom_bridge` 发布。
3. 多初值结果状态使用 `accepted_multi_seed`，可复用协调器现有的 `accepted*` 合同。
4. 超时结果不会发布恢复候选。
5. 后台旧任务不能跨 attempt 或跨地图生效。
6. 开关关闭时不创建多初值定时器、不提交后台精配任务。

## 初始参数

正式模板使用两条工作线程、初始化帧 top30 候选、最多三个候选簇、每簇三条独立轨迹。参数沿用历史完整算法：初始化聚类 `0.35m/10deg`，首帧局部搜索 `+/-0.5m/+/-20deg`，细 GICP 为 `0.10m/0.30m/50次`，rolling12 至少九帧有效，双轨迹一致门槛为 `0.08m/2deg`，单批时间预算为 `12s`。

这些参数是保守接入初值。开关正式打开前，仍需使用 bag44/45/46 对最终 Bridge 稳定 TF 链路做完整回归。

## 已完成验证

- 功能包 Release 编译通过。
- 多初值专项 C++ 测试通过：
  - 同来源候选对能够建立两条独立轨迹。
  - 两条 rolling12 稳定且一致的轨迹能够进入接受结果。
  - 只有一条稳定轨迹时被拒绝。
  - 两条稳定但 `map->odom` 分离的轨迹被一致性门控拒绝。
- 两份固定 YAML 的多初值开关均为默认关闭。
- bag45 已知困难窗口在线回放：
  - 初始化 30 个候选耗时 1.54~1.58s，形成同簇三条独立轨迹。
  - rolling12 后由三条轨迹共同通过，单次跟踪批次约 0.90~1.11s。
  - 14 个 `accepted_multi_seed` 输出与 `/robot_realpose` 按最近时间戳对齐后，平移误差平均 0.0303m、最小 0.0102m、最大 0.0733m；航向误差平均 3.04deg、最大 4.29deg。
  - 开启实验配置时平均 CPU 约 97.1%（单核口径）、峰值 135%；平均 RSS 约 221MiB、峰值 273MiB。
- 同一窗口使用正式默认配置回放时，细地图点数为 0，多初值任务调度、跟踪和接受事件均为 0，原有 temporal/trajectory 链路保持不变。
- 协调器合同测试通过：shadow、off、RO 初值下发、RO trusted commit 后 Bridge 应用均符合现有约束。
- 完整 handoff 时序探针通过：Bridge 接受后继续等待足量的新 RO 正常匹配帧，再恢复定位可信状态。

上述在线回放用于验证正式源码的开关、线程、状态和候选输出，不代表最终 Bridge 成功率。正式启用前仍需在协调器 `enforce` 模式下完成 RO trusted commit、Bridge 接受和 TF 稳定性的全链路批量回归。
