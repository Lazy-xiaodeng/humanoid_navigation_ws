本文档用于基于最近一次真实启动日志，确认当前机器人导航系统实际启动了哪些 launch、哪些节点，以及这次“路线任务 + 任意跳步 + task/transit + 播报协同”改造应该优先改哪些真正生效的文件。

## 3. 最终结论

最近一次真实启动链路不是：

1. `start_navigation.sh -> humanoid_navigation/navigation.launch.py -> navigation_state_manager_recoverable.py`

而是：

1. `start_navigation.sh`
2. `humanoid_bringup/robot_real.launch.py`
3. `humanoid_navigation/launch/navigation_fusion.launch.py`
4. `navigation_state_manager.py`

同时 websocket / APP 数据整合侧实际运行的是：

1. `websocket_server.launch.py`
2. `data_integration_node_recoverable.py`

所以当前实机最近一次真实运行是一个“混合链路”：

1. 导航状态管理器走普通版 `navigation_state_manager.py`
2. 数据整合节点走 `data_integration_node_recoverable.py`

## 4. 启动入口确认

### 4.1 根入口

最近一次真实启动中，[start_navigation.sh](/home/ubuntu/humanoid_ws/start_navigation.sh:221) 实际执行的是：

```bash
ros2 launch humanoid_bringup robot_real.launch.py use_sim_time:=false
```

这说明：

1. `start_navigation.sh` 不是直接启动 `humanoid_navigation/navigation.launch.py`
2. 现场默认入口是 `robot_real.launch.py`

### 4.2 bringup 入口

[robot_real.launch.py](/home/ubuntu/humanoid_ws/src/humanoid_bringup/launch/robot_real.launch.py:107) 中包含：

1. `navigation_fusion.launch.py`

因此当前 APP 层导航链路实际来自：

1. `humanoid_navigation/launch/navigation_fusion.launch.py`

而不是：

1. `humanoid_navigation/launch/navigation.launch.py`

## 7. 对路线任务改造最重要的结论

这次路线任务相关功能如果要优先改“最近一次真实运行时一定生效”的文件，优先级应为：

### 7.1 第一优先级

1. [navigation_state_manager.py](/home/ubuntu/humanoid_ws/src/humanoid_navigation/humanoid_navigation/navigation_state_manager.py:1)
2. [dynamic_waypoints_manager.py](/home/ubuntu/humanoid_ws/src/humanoid_navigation/humanoid_navigation/dynamic_waypoints_manager.py:1)
3. [websocket_server.py](/home/ubuntu/humanoid_ws/src/humanoid_websocket/humanoid_websocket/websocket_server.py:1)
4. [data_integration_node_recoverable.py](/home/ubuntu/humanoid_ws/src/humanoid_websocket/humanoid_websocket/data_integration_node_recoverable.py:1)

原因：

1. `navigation_state_manager.py` 是最近一次真实运行中的主状态管理器
2. `data_integration_node_recoverable.py` 是最近一次真实运行中的主数据整合器
3. websocket 和命令转发链路也都真实在线

### 7.2 第二优先级

1. [navigation_state_manager_recoverable.py](/home/ubuntu/humanoid_ws/src/humanoid_navigation/humanoid_navigation/navigation_state_manager_recoverable.py:1)

原因：

1. 它不是最近一次真实启动中主生效入口

## 8. 对另一台 Codex 的明确建议

如果另一台机器上的 Codex 要按最近一次真实运行链路优先施工，建议顺序是：

1. 先改 `navigation_state_manager.py`
2. 再改 `dynamic_waypoints_manager.py`
3. 再改 `websocket_server.py`
4. 再改 `data_integration_node_recoverable.py`
5. 最后视时间和兼容性需求，再把核心逻辑同步到 `navigation_state_manager_recoverable.py`

不要反过来把主要精力先放在：

1. `navigation_state_manager_recoverable.py`

否则有较大概率出现：

1. 代码改了
2. 但最近一次真实启动链路里并不生效
