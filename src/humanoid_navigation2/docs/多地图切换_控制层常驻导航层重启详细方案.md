# 多地图切换：控制层常驻、导航层重启详细方案

## 1. 背景和结论

当前开机真实入口是：

```text
start_all_services.sh
-> start_navigation.sh
-> ros2 launch humanoid_bringup robot_real.launch.py
```

`start_all_services.sh` 同时启动：

```text
导航 ROS 系统
APP 后端
语音服务
```

因此地图切换不能通过 `stop_all_services.sh` 或粗暴停止整个 `start_navigation.sh` 拉起的全部 ROS 进程完成。否则 websocket、中间层、地图管理节点也会退出，APP 会断开连接，收不到“正在切图、定位中、切图完成、失败原因”等状态。

最终设计结论：

```text
控制层常驻：负责 APP 连接、命令接收、地图管理、切图状态推送。
导航层重启：负责与具体地图绑定的 Nav2、RO/OP 定位、Fast-LIO、map_server 等。
```

APP 点击切换地图时，ROS 控制层不退出；只停止并重启导航层。新导航层按目标 `map_id` 同时加载：

```text
2D 栅格地图：<map_id>.yaml / <map_id>.pgm
3D 定位地图：<map_id>_open3d_grounded.pcd
```

这样才能避免“2D 已切换、3D 定位仍是旧地图”的严重错配。

## 2. 当前真实链路

### 2.1 总入口

文件：

```text
start_all_services.sh
```

当前职责：

```text
1. 调用 start_navigation.sh 启动 ROS 导航模块。
2. 启动语音服务。
3. 启动 APP 后端/中控服务。
```

建议：

```text
第一期不改它的总体结构。
只要求它仍然调用 start_navigation.sh。
start_navigation.sh 内部再拆控制层和导航层。
```

### 2.2 ROS 当前入口

文件：

```text
start_navigation.sh
```

当前职责：

```text
1. 构建工作区。
2. 清理旧导航进程。
3. 启动 robot_real.launch.py。
```

问题：

```text
robot_real.launch.py 现在同时拉起控制层和导航层。
如果切图时停止整棵 robot_real.launch.py，APP 与 ROS 连接会断。
```

### 2.3 当前 robot_real.launch.py 内容

文件：

```text
src/humanoid_bringup/launch/robot_real.launch.py
```

当前拉起的主要模块：

```text
humanoid_description/display.launch.py
navigation2_robosense_lidar.launch.py 或 navigation2.launch.py
humanoid_navigation/navigation_fusion_sc.launch.py
humanoid_websocket/websocket_server.launch.py
humanoid_locomotion/locomotion.launch.py
rviz2
```

其中：

```text
navigation2_robosense_lidar.launch.py / navigation2.launch.py 是地图绑定导航层。
navigation_fusion_sc.launch.py 里混有控制层节点和导航状态节点。
websocket_server.launch.py 是 APP 连接控制层，不能随切图停止。
```

## 3. 节点分层

### 3.1 控制层：切图时不能停

控制层职责：

```text
1. 和 APP 保持 websocket 连接。
2. 接收 map_management/switch_map。
3. 查询/维护 map_registry.json。
4. 查询/维护 data/waypoints/<map_id>.json。
5. 推送 map_switch_status / map_status。
6. 编排导航层停止、启动、ready 检查。
```

建议归入控制层的节点：

```text
websocket_server_node
data_integration_node_recoverable
message_bridge_node / websocket_client_node 如果当前 APP 链路需要
dynamic_waypoints_manager
map_context_manager 或新增 map_switch_manager
humanoid_locomotion/locomotion.launch.py
```

说明：

```text
dynamic_waypoints_manager 不依赖具体 Nav2 action，可常驻。
map_context_manager 应升级为切图编排节点，或者新增 map_switch_manager 承担编排。
locomotion 如果只是机器人动作/速度下发桥接，建议常驻；如果其中有强 Nav2 生命周期依赖，再单独拆分。
```

### 3.2 导航层：切图时停止并重启

导航层职责：

```text
1. 加载目标地图的 2D 栅格。
2. 加载目标地图的 3D 定位 PCD。
3. 建立定位 TF。
4. 启动 Nav2 planner/controller/bt_navigator。
5. 执行 route task。
```

建议归入导航层的节点：

```text
humanoid_description/display.launch.py 视 TF 依赖保留在导航层或单独基础层
rslidar_sdk_node
fastlio_mapping
point_cloud_filter_node
static_transform_publisher: tf_odom_to_camera_init / tf_map_to_ground / tf_body_to_base_footprint / tf_base_footprint_to_clearing_lidar
dynamic_odom_ground_publisher
nav2_map_server/map_server
lifecycle_manager_map
robosense_lidar_localization_node
humanoid_prior_localization_runtime/global_localization_node
fastlio_open3d_axis_adapter
prior_map_odom_bridge
robot_realpose_publisher
periodic_clearing_publisher / periodic_clearing_3d_publisher
wait_for_tf
nav2_planner/planner_server
nav2_controller/controller_server
nav2_behaviors/behavior_server
nav2_bt_navigator/bt_navigator
navigation_state_manager
rviz2 可选
```

说明：

```text
navigation_state_manager 使用 Nav2 action client、定位健康状态和 route task 运行态，属于导航层。
切图时如果存在 active route task，必须先拒绝切图或要求 APP 终止任务。
```

## 4. 需要新增或改造的脚本

### 4.1 start_all_services.sh

建议改动：

```text
暂不拆总入口。
仍调用 start_navigation.sh。
可选：允许透传 MAP_ID，例如开机服务配置里设置 MAP_ID=hall1 时，start_navigation.sh 使用该地图。
```

不建议：

```text
不要让 start_all_services.sh 直接参与运行中切图。
不要在切图时重启 APP 后端和语音服务。
```

### 4.2 start_navigation.sh

目标：

```text
启动 ROS 控制层。
按 current_map_id 或 MAP_ID 启动导航层。
```

建议改造后流程：

```text
1. 读取 data/maps/map_registry.json。
2. 如果命令行或环境变量指定 MAP_ID，则使用 MAP_ID。
3. 如果没有指定 MAP_ID，则使用 registry.current_map_id。
4. 校验目标地图 enabled=true。
5. 校验 map_yaml_file 存在。
6. 校验 open3d_prior_map_file 存在。
7. 生成 RO runtime config，确保 map_path 指向目标 open3d_prior_map_file。
8. 启动控制层 launch。
9. 启动导航层 launch，并传入 map_id、map_yaml_file、prior_map_path、robosense_config_file。
```

建议命令：

```bash
./start_navigation.sh
MAP_ID=hall1 ./start_navigation.sh
./start_navigation.sh hall1
```

注意：

```text
start_navigation.sh 只用于开机或整套 ROS 模块首次启动。
运行中切图应由控制层调用 stop/start navigation stack 脚本，而不是重新调用完整 start_navigation.sh。
```

### 4.3 新增 start_ros_control_plane.sh

目标：

```text
只启动控制层，不启动 Nav2/定位/地图绑定节点。
```

建议启动内容：

```text
dynamic_waypoints_manager
map_context_manager 或 map_switch_manager
websocket_server.launch.py
data_integration_node_recoverable
message_bridge_node / websocket_client_node
locomotion.launch.py
```

建议 launch：

```text
src/humanoid_bringup/launch/robot_control_plane.launch.py
```

脚本流程：

```text
source ROS 环境
source 当前 workspace local_setup
启动 robot_control_plane.launch.py
写入 .ros_control_plane.pid
```

### 4.4 新增 start_navigation_stack.sh

目标：

```text
只启动导航层，必须带 map_id。
```

建议命令：

```bash
./start_navigation_stack.sh hall1
MAP_ID=hall1 ./start_navigation_stack.sh
```

流程：

```text
1. 从 map_registry.json 读取目标地图。
2. 校验 map_yaml_file。
3. 校验 open3d_prior_map_file。
4. 生成 data/runtime_maps/<map_id>/robosense_lidar_localization.yaml。
5. 写 registry.current_map_id=<map_id>。
6. 启动 robot_navigation_stack.launch.py。
7. 传入：
   map_id
   map_yaml_file
   prior_map_path
   robosense_config_file
   relocalization_engine
8. 写入 .navigation_stack.pid。
```

建议 launch：

```text
src/humanoid_bringup/launch/robot_navigation_stack.launch.py
```

`robot_navigation_stack.launch.py` 应包含：

```text
display.launch.py 或基础 TF
navigation2_robosense_lidar.launch.py / navigation2.launch.py
navigation_state_manager
rviz 可选
```

注意：

```text
不要启动 websocket_server。
不要启动 dynamic_waypoints_manager。
不要启动 map_context_manager。
这些属于控制层。
```

### 4.5 新增 stop_navigation_stack.sh

目标：

```text
只停止导航层，不停止控制层。
```

停止对象：

```text
ros2 launch humanoid_bringup robot_navigation_stack.launch.py
ros2 launch humanoid_navigation2
rslidar_sdk_node
fastlio_mapping
point_cloud_filter_node
static_transform_publisher.*tf_odom_to_camera_init
static_transform_publisher.*tf_map_to_ground
static_transform_publisher.*tf_body_to_base_footprint
static_transform_publisher.*tf_base_footprint_to_clearing_lidar
dynamic_odom_ground_publisher
nav2_map_server.*/map_server
nav2_lifecycle_manager.*/lifecycle_manager_(map|navigation)
robosense_lidar_localization_node
prior_map_open3d_localization
fastlio_open3d_axis_adapter
prior_map_odom_bridge
robot_realpose_publisher
periodic_clearing_publisher
periodic_clearing_3d_publisher
wait_for_tf.*wait_for_localization_tf
planner_server
controller_server
behavior_server
bt_navigator
navigation_state_manager
rviz2.*navigation.rviz
```

不能停止：

```text
websocket_server_node
data_integration_node_recoverable
message_bridge_node
dynamic_waypoints_manager
map_context_manager / map_switch_manager
APP 后端
语音服务
```

### 4.6 stop_navigation.sh

目标：

```text
保留为“停止整个 ROS 导航模块”的运维脚本。
```

用途：

```text
stop_all_services.sh 调用它时，可以停止完整 ROS 模块。
人工排障时使用。
```

不应用于：

```text
APP 运行中切图。
```

### 4.7 switch_navigation_map.sh

目标：

```text
由控制层调用，执行一次完整地图切换。
```

建议流程：

```text
1. 输入 target_map_id。
2. 调 stop_navigation_stack.sh。
3. 调 start_navigation_stack.sh <target_map_id>。
4. 不停止控制层。
5. 日志写入 debug_logs/switch_navigation_map_<map_id>_<time>.log。
```

注意：

```text
不要调用 stop_navigation.sh。
不要调用 start_navigation.sh。
因为它们是整套 ROS 模块入口，可能影响控制层。
```

## 6. APP 切图完整流程

### 6.1 开机在旧地图，真实环境已变

例子：

```text
上次 current_map_id=hall
机器人被移动到 hall1
开机后默认导航层加载 hall
APP 连接后选择 hall1
```

流程：

```text
APP -> ROS 控制层：switch_map(hall1)
ROS 控制层：校验 hall1 注册表
ROS 控制层：校验 hall1.yaml 存在
ROS 控制层：校验 hall1_open3d_grounded.pcd 存在
ROS 控制层 -> APP：map_switch_status(validating)
ROS 控制层 -> APP：map_switch_status(stopping_navigation_stack)
ROS 控制层：调用 stop_navigation_stack.sh
ROS 控制层 -> APP：map_switch_status(starting_navigation_stack)
ROS 控制层：调用 start_navigation_stack.sh hall1
导航层：Nav2 map_server 加载 hall1.yaml
导航层：RO/OP 加载 hall1_open3d_grounded.pcd
导航层：等待定位 TF ready
导航层：navigation_state_manager 启动并发布状态
ROS 控制层 -> APP：map_status(current_map_id=hall1,map_state=ready)
APP：允许开始 hall1 路线
```

### 6.2 开机仍在同一地图

例子：

```text
上次 current_map_id=hall
机器人仍在 hall
```

流程：

```text
start_all_services.sh
-> start_navigation.sh
-> start_ros_control_plane.sh
-> start_navigation_stack.sh hall
-> hall 2D/3D ready
APP 连接后直接看到 hall ready
APP 可直接开始导航
```

### 6.3 导航中切图

流程：

```text
APP -> ROS：switch_map(hall1)
ROS 检测 active route task 或 Nav2 goal active
ROS 拒绝
```

错误码：

```text
map_switch_rejected_route_task_active
```

APP 文案：

```text
当前正在导航，请先终止导航任务后再切换地图。
```

## 8. 错误码

| error_code | 含义 | APP 建议 |
|---|---|---|
| `map_not_registered` | 地图未注册 | 提示地图不存在 |
| `map_disabled` | 地图被禁用 | 提示地图未启用 |
| `map_file_missing` | 2D 栅格地图缺失 | 提示需要重新建图或检查地图文件 |
| `prior_map_file_missing` | 3D 定位 PCD 缺失 | 提示需要重新建图或检查 PCD |
| `map_switch_rejected_route_task_active` | 导航任务运行中不允许切图 | 提示先终止导航 |
| `map_switch_stop_failed` | 停止导航层失败 | 提示切图失败并保留原地图 |
| `map_switch_start_failed` | 启动目标导航层失败 | 提示目标地图启动失败 |
| `map_switch_localization_timeout` | 新地图定位未稳定 | 提示人工检查定位或初始位姿 |
| `map_switch_nav2_timeout` | Nav2 未 ready | 提示导航栈启动失败 |
| `active_map_mismatch` | start_route_task 的 map_id 与当前 ready 地图不一致 | 后端重新查询当前地图 |

## 9. 关键保护

### 9.1 切图前必须校验 2D 和 3D

必须同时存在：

```text
map_yaml_file
open3d_prior_map_file
```

不能只校验 2D 地图。

### 9.2 切图时不能杀控制层

禁止停止：

```text
websocket_server_node
data_integration_node_recoverable
map_context_manager / map_switch_manager
dynamic_waypoints_manager
```

否则 APP 会断连，无法接收切图状态。

### 9.3 新导航层 ready 前不能开始路线任务

`start_route_task` 前必须满足：

```text
map_status.current_map_id == command.map_id
map_status.map_state == ready
localization_state == stable
Nav2 action server ready
```

### 9.4 切图失败不能污染 current_map_id

只有目标导航层启动并 ready 后，才写：

```text
registry.current_map_id = target_map_id
```

如果启动失败，应保留旧地图或进入明确 failed 状态。

## 10. 分阶段施工建议

### 阶段 1：脚本拆分

改动：

```text
新增 start_ros_control_plane.sh
新增 start_navigation_stack.sh
新增 stop_navigation_stack.sh
改造 start_navigation.sh
保留 stop_navigation.sh 作为整套 ROS 停止脚本
```

验收：

```text
./start_navigation.sh 可启动 hall
MAP_ID=hall ./start_navigation.sh 可启动 hall
MAP_ID=hall1 ./start_navigation.sh 在 hall1 文件缺失时明确失败
```

### 阶段 2：launch 拆分

改动：

```text
新增 robot_control_plane.launch.py
新增 robot_navigation_stack.launch.py
拆分 navigation_fusion_sc.launch.py
```

验收：

```text
控制层单独启动后 APP 可连接
导航层未启动时 APP 能查询地图列表
导航层启动后 APP 能收到 map_status ready
```

### 阶段 3：切图编排节点

改动：

```text
改造 map_context_manager 或新增 map_switch_manager
switch_map 调用 stop_navigation_stack.sh + start_navigation_stack.sh
推送 map_switch_status
等待 localization/Nav2 ready
```

验收：

```text
APP 切 hall -> hall1 时 websocket 不断
APP 能收到 validating/stopping/starting/waiting/ready
切图完成后 current_map_id=hall1
start_route_task(map_id=hall1) 成功进入导航
start_route_task(map_id=hall) 被 active_map_mismatch 拒绝
```

静态护栏：

```text
python3 src/humanoid_navigation2/scripts/validate_multimap_switch_static.py
```

必须通过。该脚本用于防止以下回退：

```text
switch_navigation_map.sh 又调用 stop_navigation.sh / start_navigation.sh
stop_navigation_stack.sh 误杀 websocket / map_context_manager / dynamic_waypoints_manager
navigation_control_plane.launch.py 误启动 navigation_state_manager
切图时先停旧导航层、后校验目标地图
VALIDATE_ONLY=1 误写 current_map_id
```

语义模拟：

```text
ROS_DOMAIN_ID=138 FASTDDS_BUILTIN_TRANSPORTS=UDPv4 \
python3 src/humanoid_navigation2/scripts/simulate_multimap_switch_semantics.py
```

该模拟不启动真实 Nav2/雷达/定位节点，只启动真实 `map_context_manager`，并使用临时假地图和假切图脚本验证：

```text
APP switch_map 可以触发导航层重启脚本
map_context_manager 会继续保持在线并推送 map_response/map_status
切图脚本成功后会发布 /initialpose
定位健康后会推送 map_ready
最终 current_map_id 和 map_status 均切到目标地图
```

### 阶段 4：建图和注册闭环

改动：

```text
start_mapping.sh 生成 <map_id>.yaml 和 <map_id>_open3d_grounded.pcd
自动注册 map_registry.json
自动创建 data/waypoints/<map_id>.json
不再生成 *_localization_grounded.pcd
```

验收：


## 12. 最终用户体验

客户视角应该是：

```text
1. 机器人开机。
2. APP 自动连接。
3. APP 显示当前地图和定位状态。
4. 如果当前地图不是现场地图，用户选择目标地图并点击切换。
5. APP 显示“正在切换地图/正在定位/准备完成”。
6. 切图完成后 APP 才开放开始导航按钮。
7. 用户直接开始目标地图路线。
```

客户不应该感知：

```text
手工改 JSON
手工复制 PCD
手工重启整机
手工判断 2D/3D 是否一致
```

## 13. hall1 临时测试克隆地图说明

为了在没有重新建图的情况下先验证切图链路，可以临时把 `hall` 地图复制为 `hall1`。本轮曾生成过这份测试克隆图，并在验证通过后按要求删除。

验证期间 `map_registry.json` 曾临时把 `hall1` 标记为“由 hall 克隆的测试地图”。验证完成后已移除这些测试标记，并恢复为备用地图描述。

这类测试克隆图只用于：

```text
start_navigation_stack.sh MAP_ID=hall1 VALIDATE_ONLY=1
map_context_manager switch_map 状态机验证
APP/ROS 地图切换协议联调前置测试
```

不能用于：

```text
客户真实 hall1 场景定位
真实多地图验收
长期地图资产交付
```

原因是它的 2D/3D 地图内容仍然来自 `hall`，只是文件名变成了 `hall1`。

当前 Todesk 工作区已经删除临时 `hall1` 克隆地图文件，仅保留 `data/waypoints/hall1.json` 作为点位库占位。正式使用 `hall1` 前必须重新建图生成真实地图产物。
