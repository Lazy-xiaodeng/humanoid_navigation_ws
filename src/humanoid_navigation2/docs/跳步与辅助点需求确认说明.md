# 跳步与辅助点需求确认说明

## 1. 文档目的

本文档只用于和客户、产品、项目成员确认本次“跳步导航”需求的业务语义。

本文档不是开发实现方案，不涉及代码设计、状态机、接口细节，只说明：

1. 跳步时到底怎么走
2. 哪些点是任务点，哪些点是辅助点
3. 跳步后任务如何继续
4. 客户在设置点位时需要配置什么

确认无误后，再更新正式开发文档。

## 2. 本次确认后的核心结论

### 2.1 跳步时，不再要求沿任务点顺序逐个经过

例如原始任务点顺序为：

```text
A B C D E F G
```

如果当前在 `A`，用户选择跳到 `D`，则：

1. 不再要求按 `A -> B -> C -> D` 的任务顺序去走
2. 而是直接以 `D` 作为新的目标任务点进行规划

也就是说：

**跳步的目标是直接去目标任务点，而不是继续执行中间任务点。**

### 2.2 仍然保留“辅助点/途经点”能力

虽然跳步不再要求经过中间任务点，但仍然需要保留“辅助点/途经点”。

原因：

1. 有些区域需要过窄门
2. 有些区域需要提前对正方向
3. 有些区域需要按照现场安全路径通过

因此，即使跳步时不执行中间任务点，导航过程中仍然可以自动经过中间的辅助点。

## 3. 点位分为两类

### 3.1 任务点

任务点指有业务意义的点，例如：

1. 展位讲解点
2. 停靠播报点
3. 用户可选择跳到的目标点

任务点特点：

1. 可以加入主任务序列
2. 可以触发播报
3. 可以作为跳步目标
4. 完成后推进任务进度

### 3.2 辅助点 / 途经点

辅助点指没有讲解业务语义、仅用于导航引导的点，例如：

1. 过门前对正点
2. 门内通过点
3. 回程时的引导点
4. 狭窄通道中的 through point

辅助点特点：

1. 不触发播报
2. 不作为任务完成点
3. 不单独作为讲解目标
4. 只作为导航过程中的途经点使用

## 4. 客户需要能手动设置点位类型

客户在 app 的点位设置界面，需要能明确选择该点是：

1. `任务点`
2. `辅助点`

例如：

1. 点位 `1-10` 是任务点
2. 点位 `11-12` 是辅助点
3. 点位 `19-25` 是辅助点

也就是说，点位不是系统自动猜，而是由客户在设置点位时显式指定。

## 5. 默认执行规则

### 5.1 正常顺序执行时

假设客户按顺序保存点位，序列中：

1. `10` 是任务点
2. `11`、`12` 是辅助点
3. `13` 是任务点

那么从任务点 `10` 到任务点 `13` 正常执行时，默认走法为：

```text
10 -> 11 -> 12 -> 13
```

含义：

1. `11`、`12` 会作为中间途经点自动加入
2. `11`、`12` 不停车、不播报
3. 到 `13` 才正式完成该段任务

### 5.2 跳步执行时

假设当前正在执行 `1-25` 的任务，执行到点位 `7` 时，用户选择跳到点位 `15`。

又假设：

1. 点位 `11`、`12` 被设置为辅助点
2. 点位 `8、9、10、13、14` 是任务点

则本次跳步默认走法为：

```text
7 -> 11 -> 12 -> 15
```

含义：

1. 中间任务点 `8、9、10、13、14` 不执行
2. 中间辅助点 `11、12` 自动作为途经点加入
3. 机器人直接去目标任务点 `15`

也就是说：

**跳步时跳过中间任务点，但保留中间辅助点。**

## 6. 默认吸收规则

建议当前版本采用如下默认规则：

### 规则 1

点位按客户在 UI 中的保存顺序形成有序主序列。

### 规则 2

从当前任务点到目标任务点之间：

1. 中间的 `任务点` 在跳步时不执行
2. 中间的 `辅助点` 自动作为 through point 加入

### 规则 3

辅助点加入时按顺序执行，不允许乱序插入。

例如：

1. 正确示例：
   - `7 -> 11 -> 12 -> 15`
2. 错误示例：
   - `7 -> 11 -> 12 -> 8 -> 9`

## 7. 跳步后任务如何继续

这一条必须明确。

建议采用以下规则：

**跳到哪个任务点，哪个任务点完成后，就从它继续沿任务主序列向后执行。**

### 示例 1：A 跳到 D

原始任务：

```text
A B C D E F G
```

若从 `A` 跳到 `D`：

1. 中间任务点 `B、C` 不执行
2. 若存在中间辅助点，则经过辅助点
3. 到 `D` 后正常停靠/播报
4. `D` 完成后继续去 `E`

**不会回到 `B` 重新开始。**

### 示例 2：F 跳到 B

原始任务：

```text
A B C D E F G
```

若从 `F` 跳到 `B`：

1. 中间任务点不执行
2. 可经过中间辅助点
3. 到 `B` 后正常停靠/播报
4. `B` 完成后继续去 `C`

**不会回到 `G`。**

## 8. 客户需要确认的重点问题

请客户重点确认以下几点是否符合预期：

1. 跳步时，是否允许不经过中间任务点，直接去目标任务点
2. 跳步时，是否仍然需要自动经过中间辅助点
3. 点位是否需要由客户手动设置为“任务点”或“辅助点”
4. 从某点跳到目标点后，目标点完成后是否从该点继续往后执行
5. 是否接受如下行为：
   - `A -> D` 后，`D` 完成继续 `E`
   - `F -> B` 后，`B` 完成继续 `C`

## 9. 当前建议结论

基于目前沟通，建议确认的业务规则为：

1. 跳步时，直接以目标任务点为新的导航目标
2. 中间任务点不执行
3. 中间辅助点自动作为途经点加入
4. 辅助点不停车、不播报
5. 目标任务点完成后，从该点继续沿主任务序列向后执行

## 10. 一句话总结

**跳步时直接去目标任务点，但自动保留中间辅助点作为无痕途经点；目标任务点完成后，从该点继续往后执行任务。**
