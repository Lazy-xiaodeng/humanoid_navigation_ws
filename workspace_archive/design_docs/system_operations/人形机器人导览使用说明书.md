版本日期：2026-06-04

工作空间：`/home/ubuntu/humanoid_ws`

参考资料：

本文用于说明人形机器人导览系统的日常使用、状态切换、建图、导航、充电、直流供电和常见故障处理。客户现场操作时应优先按照本文“日常导览流程”执行；需要调试或排查问题时，再参考附录中的 ROS 命令和接口示例。

## 1. 文档范围与安全要求

### 1.1 适用范围

本文适用于已完成现场部署的人形机器人导览系统，包含：

- 机器人本体和遥控器基础操作。
- 机器人 `Zero`、阻尼、站着、拟人行走或行走控制状态切换。
- 建图系统启动、建图操作和地图保存。
- 导航系统启动、APP 连接、点位设置和导览导航。
- 机器人充电、电池使用和直流供电模式。
- 日常运行检查、结束运行和常见故障处理。

本文不替代机器人原厂硬件维护手册。涉及电池规格、直流输入规格、接口定义、拆装维护和结构维修时，以设备铭牌、原厂说明、随箱电源和现场交付配置为准。

### 1.2 安全须知

使用机器人前必须确认：

1. 机器人周围至少保留安全操作空间，地面平整、干燥、无台阶、无杂物、无拖地线缆。
2. 操作人员已经熟悉急停、阻尼和零力矩操作。
3. 建图或导航前，机器人雷达、IMU、工控机、头部表情模块和底层控制服务均已上电。
4. 机器人处于站立或行走控制状态时，人员不得站在机器人腿部运动范围内。
5. 机器人行走过程中不得拉拽、推动、托举机器人。
6. 机器人出现异常晃动、路径偏离、通信中断、线缆缠绕、电量过低或环境人员拥挤时，应立即停止导航并切换到安全状态。

禁止事项：

- 禁止在楼梯、斜坡、湿滑地面、强反光地面或拥挤区域进行无人看护运行。
- 禁止使用非指定充电器、电源或直流供电设备。
- 禁止在直流供电线缆未固定、线缆可能进入腿部运动范围时启动行走或导航。
- 禁止在机器人未站稳、未完成初始化或遥控器未连接时下发导航任务。

## 2. 系统组成

### 2.1 主要组成

导览系统由以下部分组成：

- 机器人本体：执行站立、行走、转向、导览和表情动作。
- 遥控器：用于状态切换、手动移动、急停和基础控制。
- 工控机或主机：运行 Ubuntu、ROS 2 Jazzy、建图导航程序和 WebSocket 服务。
- 雷达和 IMU：用于建图、定位和导航。
- APP 或上位机：用于连接 WebSocket、查看机器人状态、设置点位和下发导航任务。
- 充电器、电池和直流供电设备：用于日常供电和固定场景运行。

### 2.2 软件链路

系统启动后，导航链路如下：

```text
雷达/IMU
  -> 雷达驱动
  -> Fast-LIO
  -> 点云滤波
  -> 建图或定位
  -> Nav2 导航栈
  -> /cmd_vel
  -> WebSocket 客户端
  -> 机器人底层行走控制

APP
  -> WebSocket 服务端
  -> 点位管理
  -> 导航状态管理
  -> Nav2 导航任务
```

正式导航主入口为：

```bash
/home/ubuntu/humanoid_ws/start_navigation.sh
```

## 3. 使用前检查

### 3.1 环境检查

每次运行前确认：

1. 地面平整，无积水、无杂物、无明显反光。
2. 导览路线中的门、展台、临时围挡、人员通道与建图时环境基本一致。
3. 机器人周围无拖线、包装物、工具箱或其他可能被脚部碰到的物体。
4. 雷达无遮挡，传感器表面无明显污渍。
5. APP 设备和机器人主机处于同一网络。

### 3.2 机器人检查

上电前确认：

1. 机器人外观无明显损伤。
2. 关节、腿部和脚部无异物卡住。
3. 电池已安装到位，或直流供电线缆已按现场要求连接。
4. 急停按钮处于可释放状态。
5. 遥控器电量充足并可正常开机。

### 3.3 主机检查

主机应满足：

- 已进入 Ubuntu 桌面。
- 工作空间路径为：`/home/ubuntu/humanoid_ws`
- ROS 2 版本为 Jazzy。
- 工作空间已编译并存在：`/home/ubuntu/humanoid_ws/install/setup.bash`

打开终端后可执行：

```bash
cd /home/ubuntu/humanoid_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
```

## 4. 机器人基础状态

机器人常用状态包括 零力矩、阻尼、站着、拟人行走。现场操作应按顺序切换，不应跨状态直接进入行走。

### 4.1 Zero / 零力矩状态

用途：

- 机器人初始化、校零或人工调整姿态。
- 关节无主动驱动力，可由操作人员手动摆放。
- 异常处理时可作为安全准备状态。

操作说明：

- 官方遥控器资料中，零力矩常用组合为 `L2 + ○`。
- 进入零力矩后，机器人不会主动保持站姿。操作人员必须扶稳机器人，避免倾倒。在切换到零力矩状态时，务必将机器人用吊架吊起并保持稳定

注意：

- 非拟人行走状态下禁止下发导航或行走命令。
- 需要搬动或调整机器人姿态时，应由两名以上人员配合，防止机器人失稳。

### 4.2 校零

用途：

- 使机器人关节回到系统识别的标准零位。
- 通常在升级固件、姿态异常或维护后执行。

操作说明：

1. 先让机器人进入零力矩状态。
2. 按官方遥控器说明执行校零操作，常用组合为长按 `L1` + 长按 `R1`。
3. 等待机器人完成校零提示或状态稳定。

注意：

- 校零前应确认机器人被可靠支撑或处于官方要求姿态，一般需要吊架吊起，让机器人脚部高于吊架支撑腿。
- 校零过程中不得强行掰动关节。

### 4.3 阻尼状态

用途：

- 机器人关节带阻尼力，适合人工扶持、保护、准备起身或异常恢复。
- 相比零力矩，关节不再完全自由摆动。

操作说明：

- 官方遥控器资料中，阻尼常用组合为 `L2+Down+X`。
- 建议从零力矩状态切换到阻尼状态。

注意：

- 阻尼状态不是正式导览运行状态。
- 阻尼状态下不建议下发导航任务。

### 4.4 站着状态

用途：

- 机器人完成起身并保持平衡。
- 导航和行走控制前必须先确认机器人已经站稳。

操作说明：

- 官方遥控器资料中，站着常用组合为 `L2 + △`。
- 切换后等待机器人站稳，确认无明显晃动、无异常报警。

注意：

- 机器人站立后，人员应离开腿部运动范围。
- 如果机器人站立失败或出现异常晃动，应立即停止操作，切换到阻尼或急停处理。

### 4.5 拟人行走 / 行走控制状态

用途：

- 机器人接收遥控器摇杆或导航系统速度指令，执行前进、后退、横移和转向。
- 本系统导航时，Nav2 会输出 `/cmd_vel`，再由 WebSocket 客户端转成机器人底层行走指令。

操作说明：

1. 先确认机器人处于站着状态。
2. 使用遥控器短距离测试前后移动和原地转向。
3. 确认机器人可正常响应后，再启动导航系统。

说明：

- 部分官方版本中，站着状态即可直接进入行走控制，不再单独切换“拟人行走”模式。
- 客户现场可以将“拟人行走”理解为机器人已站稳、可接收行走控制指令的运行状态。

注意：

- 行走控制前必须确认线缆、人员和障碍物不会进入脚部运动范围。
- 如果 `/cmd_vel` 有输出但机器人不走，应检查机器人底层是否已进入可行走状态。

## 5. 开机、关机与急停

### 5.1 开机流程

1. 使用吊架将机器人吊起，确保机器人脚部离地10cm左右、清理机器人周围环境。
2. 确认电池或直流供电连接正常。
3. 按下机器人电池上的开机键（方法是：先短按一次，电池指示灯常亮，松开手再次长按一次，机器人成功开机后，会听到滴滴滴声音），打开机器人本体电源。
4. 打开遥控器，等待遥控器与机器人连接。
5. 释放急停，确认机器人无报警。
6. 按顺序进入零力矩、阻尼、站着、拟人行走状态。（其中当用遥控器将机器人从阻尼切换到站着状态时候，再将机器人从吊架放下，当机器人脚部接触地面后，此时再往下放一点，机器人会自动进入拟人行走模式）
7. 短距离测试行走控制，确认机器人响应正常。

### 5.2 关机流程

1. 停止 APP 导航任务。
2. 停止 ROS 导航程序。
3. 将机器人使用吊架吊起，确保脚部离地10cm左右。
4. 使用遥控器让机器人依次切换到阻尼、零力矩模式。
5. 按下电池上的按键，关机操作和开机操作相同。
6. 关闭遥控器和主机，整理充电器、线缆和现场设备。

### 5.3 急停处理

急停按钮用于最后安全保护，不作为普通暂停、停止导航或关机手段。按下机器人急停后，机器人关节会失能，机器人会瘫倒；如机器人未挂在吊架上，可能直接倒地并造成设备损坏或人员风险。因此，除非已经做好防护或存在必须立即断能的危险情况，不可轻易按下急停。

以下情况可考虑急停：

- 机器人动作异常、持续晃动或无法站稳。
- 电池、电源、主机或传感器出现异常气味、发热、冒烟或报警。
- 机器人已经挂在吊架上，且需要立即切断关节驱动。
- 已无法通过 APP 停止、遥控器停止或切换阻尼等方式安全控制机器人。

急停后处理：

1. 不要立即恢复运行。
2. 必须先使用吊架或人工防护固定机器人，防止机器人瘫倒或二次滑落。
3. 检查机器人状态、电源、网络和导航程序。
4. 确认急停原因已排除后，按“开机流程”重新恢复，不要直接继续原导航任务。

注意：必要时按下急停前，必须尽量先将机器人挂在吊架上，防止机器人关节失能后瘫倒在地。

## 6. 充电、电池与直流供电

### 6.1 机器人电池使用

使用要求：

- 仅使用随设备交付或原厂指定电池。
- 电池安装后应确认锁止到位。
- 电池电量不足时应停止导览任务，避免机器人在行走中断电。
- 长时间不使用时，应按原厂要求存放电池。

注意：

- 机器人电池容量、额定电压、额定电流、充电接口和充电时长以设备铭牌、原厂电池标签和现场交付资料为准。
- 不得使用破损、鼓包、进水、接口松动或异常发热的电池。

### 6.2 机器人充电

推荐流程：

1. 停止导航任务，让机器人处于安全姿态。
2. 关闭不必要的运动控制或按现场交付要求关机。
3. 连接原厂或指定充电器。
4. 检查充电器指示灯、电池指示灯和接口连接状态。
5. 充电期间安排人员巡检，避免线缆被踩踏或拉拽。
6. 充电完成后先断开充电器，再恢复机器人运行。

禁止事项：

- 禁止边充电边行走。
- 禁止使用非指定充电器。
- 禁止在高温、潮湿、易燃物附近充电。
- 禁止充电接口松动时继续使用。

### 6.3 遥控器充电与电量提示

根据官方遥控器资料：

- 遥控器通过 Type-C 接口充电。
- 充电输入以官方说明为准，常见说明为 `5V / 500mA`。
- 电量低于约 20% 时，指示灯会变红。
- 电量极低时，红灯会闪烁；电量耗尽后遥控器会自动关机。

建议：

- 每次导览前确认遥控器电量充足。
- 遥控器低电量时不要开始长时间导览。
- 遥控器充电线应与机器人行走区域分离。

### 6.4 直流供电模式

直流供电模式适用于固定展示、调试、长时间待机或现场交付指定场景。直流供电不是普通移动导览的默认模式。

使用前确认：

1. 直流电源为原厂或现场交付指定设备。
2. 输出电压、电流、极性和接口与机器人要求一致。
3. 电源线、转接线和接口无破损、无松动、无明显发热。
4. 线缆已经固定，不会进入机器人腿部、脚部、雷达或人员通道范围。
5. 操作人员在场监护。

推荐流程：

1. 关闭机器人运动任务。
2. 确认机器人处于安全姿态，并放置在地图原点或现场指定起始点。
3. 先连接机器人侧直流供电接口。连接机器人侧供电接口后，机器人会自动开机。
4. 再连接 220 V 供电插座侧，也就是直流电源设备输入侧。
5. 观察机器人和电源指示状态，确认供电正常。
6. 仅在固定展示或调试场景下运行系统。
7. 结束后先停止机器人程序。
8. 断开直流供电时，先拔下或断开 220 V 供电插座侧。
9. 再断开或拔下机器人侧直流供电接口。
10. 断开直流供电后，机器人会使用电池继续供电。

注意：

- 直流供电并非传统热插拔技术，现在是可以做到边插电边用，但还是要配合电池来使用，直驱电源给机器电池供电，电池给机器供电，类似于我们的电脑电源这种工作方式，不可以只用有线不插电池来开机使用，正常开关机使用和之前没差别
- 现场演示需要使用直流供电时，必须先将机器人放置在原点或现场指定起始点，再连接机器人侧供电接口；否则机器人自动开机后可能出现定位起点不一致。
- 避免电池在上电亮灯的情况下直接插上或取下；
- 如果需要机器人移动或执行导航，应优先使用电池供电。
- 如必须在直流供电下短距离移动，必须由现场技术人员确认线缆路线，并安排专人管理线缆。
- 电压、电流和接口型号不得凭经验替代，应以设备铭牌、原厂电源和现场交付配置为准。

## 7. 建图系统使用

建图用于首次部署、环境变化较大或需要重新生成导航地图时。日常导览不需要每次建图。

### 7.1 建图前准备

1. 清理现场环境，移除临时障碍物，尽量避免动态障碍物。
2. 确认机器人电量充足或供电稳定。
3. 确认雷达、IMU 和主机正常工作。
4. 确认机器人可进入站着和行走控制状态。
5. 在 Ubuntu 桌面打开终端或者通过ssh访问主机终端。

加载环境：

```bash
cd /home/ubuntu/humanoid_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
```

### 7.2 一键启动建图

打开终端，执行：

```bash
cd /home/ubuntu/humanoid_ws
./start_mapping.sh
```

脚本会自动完成以下工作：

- 启动 `robot_mapping.launch.py` 建图系统。
- 启动 PCD 点云地图保存器。
- 同步录制建图 rosbag。
- 建图完成后保存 2D 栅格地图。
- 保存 slam_toolbox posegraph。
- 基于 rosbag 构建 Scan Context 数据库。
- 生成标准坐标系 PCD 和定位用 PCD。
- 检查地图、PCD、posegraph、Scan Context 数据库和 rosbag 是否完整。

默认输出为：

```text
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/maps/hall.yaml
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/maps/hall.pgm
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/maps/hall.posegraph
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/maps/hall.data
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/maps/hall_sc.bin
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/pcd/hall.pcd
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/pcd/hall_standard.pcd
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/pcd/hall_localization_grounded.pcd
/home/ubuntu/fast-lio-bags/hall_mapping_时间戳
```

如需指定地图名称，可在脚本后追加名称：

```bash
cd /home/ubuntu/humanoid_ws
./start_mapping.sh hall
```

启动后等待 10 到 20 秒，确认 RViz 中出现点云、机器人模型和地图信息。建图过程中保持脚本终端打开，不要关闭。

### 7.3 建图操作要求

建图时应：

1. 让机器人缓慢、平稳地覆盖全部导览区域。
2. 每条走廊、展台前方、转角和目标点附近都应覆盖。
3. 避免快速旋转、急停急走和大幅晃动。
4. 避免遮挡雷达。
5. 避免人员持续跟随在机器人近距离前方。
6. 建图路线尽量形成闭环，便于地图一致性优化。

建图效果检查：

- RViz 中地图边界清晰。
- 墙体、展台和通道位置无明显重影。
- 机器人轨迹连续，无大幅跳变。
- 地图覆盖了所有导览点和通行区域。

### 7.4 完成建图并自动保存

完成环境覆盖后，优先在运行 `./start_mapping.sh` 的终端输入 `finish` 后按回车，让脚本进入保存流程；也可以按 `Ctrl+C` 触发同一保存流程：

```text
finish
# 或按 Ctrl+C
```

如果建图终端一直刷新日志，看不清正在输入的内容，可以不要在该终端输入。另开一个 Ubuntu 终端，执行：

```bash
echo finish > /home/ubuntu/humanoid_ws/.start_mapping.command
```

脚本会在建图终端检测到该命令，并自动进入保存流程。

输入 `finish` 或按下 `Ctrl+C` 表示建图采集完成。脚本随后会自动进入保存流程：

1. 停止 rosbag 录制并等待 bag 写入完成。
2. 停止 PCD 保存器并保存 `hall.pcd`。
3. 调用 `/map_save` 保存 Fast-LIO 点云地图。
4. 调用 `/slam_toolbox/save_map` 保存 2D 栅格地图。
5. 调用 `/slam_toolbox/serialize_map` 保存 posegraph。
6. 通过 `build_sc_database.py` 构建 Scan Context 数据库。
7. 生成 `hall_standard.pcd` 和 `hall_localization_grounded.pcd`。
8. 检查所有必要文件是否存在且非空。
9. 停止建图 launch 并结束脚本。

保存过程中终端会持续输出阶段进度，例如 `[1/8]` 到 `[8/8]`，并在耗时较长的步骤中每隔数秒输出 `RUNNING` 提示。只有看到 `[1/8]` 这类阶段进度，才表示脚本已经真正进入保存流程。保存期间不要关闭终端、不要再次按 `Ctrl+C`、不要断电，等待脚本打印完成或失败结果。

脚本结束时如果显示 `Mapping completed successfully.`，表示建图和保存流程完成。若提示缺少文件，应根据脚本日志检查对应保存步骤。

如果建图过程中发现地图明显漂移、路线走错、现场临时遮挡严重或其他异常，本次建图应作废，不要进入保存流程。在运行 `./start_mapping.sh` 的终端输入：

```text
abort
```

如果建图终端一直刷新日志，也可以另开一个 Ubuntu 终端执行：

```bash
echo abort > /home/ubuntu/humanoid_ws/.start_mapping.command
```

输入 `abort` 后脚本会停止 rosbag、PCD 保存器和建图 launch，但不会保存 2D 地图、posegraph、Scan Context 数据库，也不会检查输出文件。确认进程退出后，可以重新执行：

```bash
cd /home/ubuntu/humanoid_ws
./start_mapping.sh
```

注意：

- `finish` 或 `Ctrl+C`：表示本次地图有效，进入保存和检查流程；现场操作优先输入 `finish`。
- `abort`：表示本次地图作废，只停止建图流程，不保存最终地图。
- 保存过程中不要再次按 `Ctrl+C`、不要关闭终端、不要断电，等待脚本打印完成或失败结果。

## 8. 导航系统使用

### 8.1 导航前准备

1. 确认机器人已开机，遥控器连接正常。
2. 确认机器人已经进入站着或行走控制状态。
3. 确认现场环境与地图基本一致。
4. 确认 APP 设备和机器人主机在同一网络。
5. 确认电池电量足够完成本次导览。

### 8.2 启动导航系统

打开终端，执行：

```bash
cd /home/ubuntu/humanoid_ws
./start_navigation.sh
```

脚本会自动启动机器人模型、导航栈、点位管理、导航状态管理、WebSocket 和表情控制。当前正式导航默认不打开 RViz；如需可视化调试，由现场技术人员单独启动 RViz。

启动后等待系统稳定，正常现象包括：

- APP 可以连接 WebSocket 服务。
- `/robot_realpose` 有机器人实时位姿。
- 机器人未收到导航任务前保持待机。

#### 设置 `start_all_services.sh` 开机自启（推荐）

如果现场需要机器人主机每次开机后自动拉起导航、语音和 APP 中控，推荐把一键启动脚本注册为 `systemd --user` 服务。该方式更适合当前 `start_all_services.sh` 的运行环境，也便于后续启用、停用和查看日志。

说明：

- 自启脚本路径：`/home/ubuntu/humanoid_ws/start_all_services.sh`
- 停止脚本路径：`/home/ubuntu/humanoid_ws/stop_all_services.sh`
- 本配置建议由现场技术人员执行一次，后续客户操作人员通常不需要重复设置。

1. 创建用户级 `systemd` 服务目录：

```bash
# 创建 ubuntu 用户自己的 systemd 服务目录；如果目录已存在也不会报错
mkdir -p /home/ubuntu/.config/systemd/user
```

2. 新建服务文件 `/home/ubuntu/.config/systemd/user/humanoid-start-all.service`，内容如下：

```ini
[Unit]
Description=Humanoid Guided Tour Auto Start
Wants=network-online.target
After=network-online.target

[Service]
Type=oneshot
WorkingDirectory=/home/ubuntu/humanoid_ws
Environment=HOME=/home/ubuntu
Environment=USER=ubuntu
Environment=LOGNAME=ubuntu
Environment=SERVICE_AUTO_START=1
Environment=CLEAN_OLD_SPEECH=1
ExecStart=/home/ubuntu/humanoid_ws/start_all_services.sh
ExecStop=/home/ubuntu/humanoid_ws/stop_all_services.sh
RemainAfterExit=yes
TimeoutStartSec=180
TimeoutStopSec=90
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=default.target
```

服务文件字段说明：

- `[Unit]`：定义服务的基础信息和启动依赖关系。
- `Description=Humanoid Guided Tour Auto Start`：服务名称说明，方便后续用 `systemctl` 查看。
- `Wants=network-online.target`：声明本服务希望在网络就绪后再启动。
- `After=network-online.target`：要求本服务排在网络就绪之后启动，避免开机太早导致网络相关模块未准备好。
- `[Service]`：定义服务本体如何启动、停止和保持状态。
- `Type=oneshot`：表示启动命令执行完成后即认为“启动动作已完成”，适合这种脚本式一键启动服务。
- `WorkingDirectory=/home/ubuntu/humanoid_ws`：指定脚本运行目录为工作空间根目录。
- `Environment=HOME=/home/ubuntu`：显式指定用户家目录环境变量，避免开机环境不完整。
- `Environment=USER=ubuntu`：显式指定运行用户名称。
- `Environment=LOGNAME=ubuntu`：显式指定登录用户名环境变量。
- `Environment=SERVICE_AUTO_START=1`：告诉 `start_all_services.sh` 当前是“开机自启模式”，让脚本按自启场景准备运行环境。
- `Environment=CLEAN_OLD_SPEECH=1`：启动前清理旧语音进程，避免上次异常退出后的残留进程影响本次启动。
- `ExecStart=/home/ubuntu/humanoid_ws/start_all_services.sh`：服务启动时执行的一键启动脚本。
- `ExecStop=/home/ubuntu/humanoid_ws/stop_all_services.sh`：服务停止时执行的一键停止脚本。
- `RemainAfterExit=yes`：即使 `ExecStart` 脚本本身已经退出，也让 `systemd` 记住该服务处于“已启动”状态，便于后续执行 `stop`。
- `TimeoutStartSec=180`：启动动作最长允许 180 秒，超时则判定启动失败。
- `TimeoutStopSec=90`：停止动作最长允许 90 秒，超时则判定停止失败。
- `StandardOutput=journal`：标准输出写入 `systemd journal` 日志。
- `StandardError=journal`：标准错误也写入 `systemd journal` 日志，方便统一排查。
- `[Install]`：定义该服务被 `enable` 后挂到哪个启动目标。
- `WantedBy=default.target`：表示执行 `systemctl --user enable` 后，该服务会随用户默认启动目标一起自动拉起。

3. 让 `ubuntu` 用户的 `systemd --user` 在开机时自动存在，并立即启用服务：

```bash
# 允许 ubuntu 用户在未登录桌面的情况下也能在开机后自动运行用户级 systemd 服务
sudo loginctl enable-linger ubuntu
# 重新加载用户级 systemd 配置，让新建的服务文件生效
systemctl --user daemon-reload
# 立即启用并马上启动 humanoid-start-all.service
systemctl --user enable --now humanoid-start-all.service
```

4. 检查是否启用成功：

```bash
# 查看服务当前状态，确认是否已经启动、是否有报错
systemctl --user status humanoid-start-all.service
# 查看该服务是否已经设置为开机自启
systemctl --user is-enabled humanoid-start-all.service
# 查看该服务最近 100 行运行日志，便于排查启动问题
journalctl --user -u humanoid-start-all.service -n 100 --no-pager
```

5. 建议执行一次重启验证：

```bash
# 重启主机，验证开机后是否会自动拉起导航、语音和 APP 中控服务
sudo reboot
```

重启后可检查：

```bash
# 再次查看服务状态，确认开机后服务是否自动启动成功
systemctl --user status humanoid-start-all.service
# 查看一键启动主日志，确认各模块启动过程是否正常
tail -n 100 /home/ubuntu/service_logs/startup_main.log
```

#### 取消开机自启

如需取消 `start_all_services.sh` 开机自启，执行：

```bash
# 取消开机自启，并立即停止当前正在运行的 humanoid-start-all.service
systemctl --user disable --now humanoid-start-all.service
# 查看当前状态，确认服务已停止且不再自启
systemctl --user status humanoid-start-all.service
```

说明：

- `systemctl --user stop humanoid-start-all.service` 只是停止“当前这一次”正在运行的整套服务，不会影响下次开机自启。
- `systemctl --user disable --now humanoid-start-all.service` 才是取消开机自启；执行后本次会停止，后续开机也不会再自动启动。

如果后续不再需要任何 `ubuntu` 用户开机自启动的 `systemd --user` 服务，还可以额外关闭 linger：

```bash
# 关闭 ubuntu 用户的 linger；关闭后，用户级 systemd 服务将不再随开机自动存在
sudo loginctl disable-linger ubuntu
```

注意：只有确认 `ubuntu` 用户下没有其他依赖开机自启的用户级服务时，才执行这一步。

#### 手动启动、手动停止和日志排查

设置完成后，除重启自动拉起外，也可以通过 `systemd` 手动控制：

```bash
# 手动启动一键服务，会执行 start_all_services.sh
systemctl --user start humanoid-start-all.service
# 手动停止一键服务，会执行 stop_all_services.sh，停止导航、语音和 APP 中控
systemctl --user stop humanoid-start-all.service
# 手动重启一键服务，等同于先停止再重新启动
systemctl --user restart humanoid-start-all.service
```

常用排查命令：

```bash
# 查看当前服务状态、退出码和最近一次启动/停止结果
systemctl --user status humanoid-start-all.service
# 查看该服务最近 200 行 systemd 日志
journalctl --user -u humanoid-start-all.service -n 200 --no-pager
# 查看一键启动总日志
tail -n 200 /home/ubuntu/service_logs/startup_main.log
# 查看一键停止总日志
tail -n 200 /home/ubuntu/service_logs/stop_main.log
```

补充说明：

- `start_all_services.sh` 会依次启动导航、语音和 APP 中控，不只是导航。
- `systemctl --user stop humanoid-start-all.service` 会调用 `/home/ubuntu/humanoid_ws/stop_all_services.sh` 做完整停止。
- 如果只是临时关闭当前导航任务，不要直接停整个服务，应优先在 APP 中停止任务，或按本文后文流程执行 `./stop_navigation.sh`。

### 8.3 RViz 调试使用说明

当前正式导航默认不打开 RViz。RViz 仅用于现场技术人员建图检查、导航调试、定位校准和问题排查；客户正式导览时，以 APP 多点导航流程为准。

单独打开 RViz：

```bash
cd /home/ubuntu/humanoid_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
rviz2 -d src/humanoid_navigation2/rviz/navigation.rviz
```

显示检查：

1. RViz 左侧 `Displays` 中确认 `Map`、`RobotModel`、`TF`、路径和点云显示已勾选。
2. `Global Options` 中 `Fixed Frame` 应为 `map_ground`。
3. 地图显示话题为 `/map`，机器人模型应与现场机器人位置基本一致。
4. 如果地图未显示，可先检查 `/map` 是否有数据；如果机器人模型不显示，可检查 TF 链路。

视角操作：

- 拖动视角：选择顶部工具栏 `Move Camera`，按住鼠标左键拖动。
- 放大缩小：使用鼠标滚轮，或按住鼠标中键调整视角。
- 平移显示区域：在俯视图下拖动地图，使机器人和目标区域位于显示区中央。
- 回到机器人附近：在 `Views` 中确认目标跟随 `base_footprint`，或手动缩放到机器人模型附近。

手动设置初始位姿：

1. 确认机器人已经停止移动，不在执行导航任务。
2. 在 RViz 顶部工具栏选择 `2D Pose Estimate`。
3. 在地图中机器人实际所在位置点击并拖出朝向箭头。
4. 松开鼠标后，RViz 会向 `/initialpose` 发布初始位姿。
5. 等待机器人模型和实际位置对齐，再观察定位是否稳定。

注意：手动初始位姿只用于启动定位失败、机器人被搬动后重定位、定位漂移排查等调试场景。正式导览任务执行中不得随意发布 `/initialpose`，否则可能导致定位跳变和路径异常。

手动选择导航目标点：

1. 确认当前没有 APP 多点导航任务在执行。
2. 在 RViz 顶部工具栏选择 `Nav2 Goal` 或 `2D Goal Pose`。
3. 在地图中点击测试目标点并拖出目标朝向。
4. 观察全局路径、局部路径、机器人起步和到达状态。

禁止：RViz 手动目标点仅用于单点调试、路径验证和现场排障，不能在执行 APP 多点导航任务时使用。正式导览过程中如需调整任务，应先在 APP 中停止当前任务，再按现场流程重新下发多点导航。

### 8.4 巡航速度设置

巡航速度属于导航参数调整项，应由现场技术人员修改，不建议客户操作人员临时改动。

当前系统未将巡航速度作为 APP 运行时动态调节入口开放。正式调整入口为 ROS 导航参数文件，修改后需要重启导航系统生效。

当前正式导航使用：

```text
启动入口：/home/ubuntu/humanoid_ws/start_navigation.sh
导航链路：humanoid_bringup/robot_real.launch.py -> humanoid_navigation2/navigation2_robosense_lidar.launch.py
参数文件：/home/ubuntu/humanoid_ws/src/humanoid_navigation2/config/nav2_params.yaml
速度入口：controller_server.ros__parameters.FollowPath.desired_linear_vel
```

修改方法：

1. 使用文本编辑器打开参数文件：

```bash
cd /home/ubuntu/humanoid_ws
nano src/humanoid_navigation2/config/nav2_params.yaml
```

2. 找到：

```yaml
controller_server:
  ros__parameters:
    FollowPath:
      desired_linear_vel: 0.5
```

3. 修改 `desired_linear_vel` 后保存文件。
4. 重新启动导航：

```bash
cd /home/ubuntu/humanoid_ws
./start_navigation.sh
```

设置建议：

- 正常巡航建议先在 `0.25~0.40 m/s` 范围内测试。
- 机器人行走稳定、路线宽、人员少时，可适当提高。
- 机器人晃动、转弯不稳、避障不稳或人员密集时，应降低。
- 调整后必须用 APP 多点导航完成完整路线测试，再用于正式导览。

注意：`desired_linear_vel` 是 Nav2 控制器的期望巡航线速度，不等同于机器人硬件最大速度。实际速度还会受路径曲率、目标接近减速、避障、加速度限制和机器人底层控制影响。

### 8.5 定位漂移处理

定位漂移常见表现：

- RViz 或 APP 中机器人位置与现场实际位置明显不一致。
- 机器人规划路径看似正常，但实际行走逐渐偏离路线。
- 机器人在转角、长走廊、玻璃墙、临时展架附近频繁修正或停顿。
- APP 显示定位置信度下降、导航状态异常或到点失败。

现场处理流程：

1. 立即在 APP 中停止导航任务，不要继续下发新的多点导航。
2. 让机器人保持站立或可控状态，必要时用遥控器短距离移到空旷安全区域。
3. 检查雷达是否被遮挡，现场环境是否与建图时差异过大。
4. 将机器人移动到地图中容易识别的位置，例如起点、宽阔走廊、固定展台旁或明显地标附近。
5. 等待定位自动恢复；如果仍不恢复，由技术人员打开 RViz 检查地图、机器人模型和 TF。
6. 若机器人实际位置与 RViz 显示不一致，可在停止导航状态下使用 `2D Pose Estimate` 重新设置初始位姿。
7. 重新用 APP 下发短路线多点导航测试，确认稳定后再恢复正式导览。

需要重建地图的情况：

- 展厅布局、展台位置或大面积遮挡与原地图明显不同。
- 多个固定区域反复出现定位漂移。
- RViz 中点云、地图边界或可通行区域存在明显重影。
- 手动设置初始位姿后仍无法稳定定位。

禁止：定位漂移时不得边执行导航任务边手动发布 RViz 目标点或初始位姿。应先停止任务，再处理定位问题。

### 8.6 APP 连接

APP 连接前确认：

1. APP 设备与机器人主机在同一网络。
2. APP 使用的 IP 为机器人 ROS 主机 IP。
3. WebSocket 服务已随 `./start_navigation.sh` 启动。
4. 服务端默认监听端口以现场配置为准，常见为 `8765`。

连接成功后，APP 应收到连接确认，并可订阅：

- 机器人实时位姿。
- 机器人速度。
- 导航状态。
- 点位数据。
- 系统状态。
- 动作执行结果。

### 8.7 设置点位

点位用于保存导览目标。常见点位类型：

- 普通导航目标点。
- 展台讲解点。
- 充电点。
- 休息点。
- 地标点。
- 障碍标记点。

设置点位建议：

1. 点位应设置在地图自由区域，不要贴墙或贴展台太近。
2. 目标点附近应有足够转身空间。
3. 展台讲解点应保证机器人朝向展台或客户指定方向。
4. 充电点和休息点应设置在人员不易碰撞的位置。
5. 设置后先把该点加入多点导航测试路线，确认机器人可稳定到达。

### 8.8 多点导航

适用场景：

- 按固定路线巡航多个展台。
- 展厅标准导览路线。
- 当前客户现场正式使用的导航方式。

操作流程：

1. 在 APP 中选择多个点位并排序。
2. 下发多点导航。
3. 机器人按顺序前往各点。
4. 观察机器人起步、路径、避障和每个点位到达状态。
5. 导航完成后确认 APP 收到完成状态。

### 8.9 暂不使用的导航接口

当前系统接口中保留了单点导航和展台导航能力，但客户现场正式导览暂不使用：

- 单点导航：`start_single_navigation`，暂不作为客户导览流程。
- 展台导航：`start_exhibition_navigation`，暂不作为客户导览流程。

如需启用上述接口，应先由现场技术人员完成联调、测试和验收。

### 8.10 暂停、恢复和停止导航

暂停导航：

- 用于临时避让人员、等待通道恢复或短暂停留。
- 暂停后机器人应停止移动，但任务上下文保留。

恢复导航：

- 确认通道恢复、安全风险解除后恢复。
- 恢复前观察机器人朝向和周围障碍物。

停止导航：

- 用于终止当前任务。
- 停止后如需继续导览，应重新选择任务或点位。

停止导航系统进程：

APP 中的“停止导航”只取消当前导航任务，不等同于关闭 Ubuntu 主机上运行的 ROS 导航系统。日常结束导览或需要重启导航系统时，在 Ubuntu 终端执行：

```bash
cd /home/ubuntu/humanoid_ws
./stop_navigation.sh
```

停止脚本会清理主 launch 以及雷达、定位、Nav2、WebSocket、TF、RViz 等残留节点；先发送 `SIGINT`，仍未退出再发送 `SIGTERM`，最后使用 `SIGKILL` 兜底。停止后确认：

```bash
source install/setup.bash
ros2 node list --no-daemon
```

如现场启用了导航漂移在线监控页面，还需要停止两个 systemd 服务；否则 `/nav_drift_live_web` 会被自动重启：

```bash
sudo systemctl stop nav-drift-live-56781.service nav-drift-static-56780.service
ros2 daemon stop
ros2 node list --no-daemon
```

注意：不要通过再次执行 `./start_navigation.sh` 来停止导航系统。该脚本会先清理旧进程，然后重新启动一套新的导航系统。

停止全部导览服务：

如果本次是通过 `/home/ubuntu/humanoid_ws/start_all_services.sh` 一键启动，或需要同时关闭导航、语音和 APP 中控服务，使用全量停止脚本：

```bash
/home/ubuntu/humanoid_ws/stop_all_services.sh
```

该脚本会依次停止：

1. 导航模块：调用 `/home/ubuntu/humanoid_ws/stop_navigation.sh`，清理 ROS 导航、雷达、定位、Nav2、WebSocket、TF、RViz 等进程。
2. 语音模块：停止 `/home/ubuntu/asr-client/listening_sound.py`、`asr-client-master.1.0.jar` 以及录音子进程 `arecord`。
3. APP 中控模块：优先停止 `backend.service`，并兜底清理 `/data/dev-ops/server/guided-tour-robot-app.jar` 进程。

停止后可确认：

```bash
ps -ef | grep -E 'asr-client|guided-tour-robot-app|humanoid_ws/install|nav2_|rslidar|robosense' | grep -v grep
```

如果没有输出，说明导航、语音和 APP 中控进程均已退出。全量停止会关闭 APP 后端服务，APP 会断开连接；仅临时取消当前导航任务时，不要使用该脚本。

## 9. 日常导览流程

### 9.1 开始导览

1. 清理导览区域，确认路线无临时障碍。
2. 检查机器人电量、遥控器电量和网络。
3. 打开机器人本体和遥控器。
4. 按顺序切换到零力矩、阻尼、站着状态。
5. 短距离测试遥控器行走控制。
6. 打开 Ubuntu 终端，执行：

```bash
cd /home/ubuntu/humanoid_ws
./start_navigation.sh
```

7. 等待导航系统启动完成。当前正式导航默认不打开 RViz，如需调试可由技术人员单独打开 RViz。
8. APP 连接 WebSocket 服务。
9. APP 订阅机器人状态和点位数据。
10. 选择多点导航任务。
11. 现场人员保持监护，随时准备暂停或停止导航；急停仅在必要且有防瘫倒措施时使用。

### 9.2 导览中巡检

导览过程中观察：

- 机器人是否按规划路线移动。
- APP 导航状态是否正常更新。
- 周围人员是否进入危险范围。
- 机器人是否出现异常晃动、频繁停顿或路径偏移。
- 电池电量是否足够。
- 直流供电线缆是否安全，如使用直流供电模式。

### 9.3 结束导览

1. 在 APP 中停止当前导航任务。
2. 确认机器人已停止移动。
3. 在 Ubuntu 终端停止导航系统进程；如果本次是用 `/home/ubuntu/humanoid_ws/start_all_services.sh` 一键启动，建议改用 `/home/ubuntu/humanoid_ws/stop_all_services.sh` 同时关闭导航、语音和 APP 中控：

```bash
cd /home/ubuntu/humanoid_ws
./stop_all_services.sh
```

如果是仅关闭导航ros相关进程采用
```bash
cd /home/ubuntu/humanoid_ws
./stop_navigation.sh
```

4. 如果现场启用了导航漂移在线监控页面，同时停止：

```bash
sudo systemctl stop nav-drift-live-56781.service nav-drift-static-56780.service
```

5. 确认 `ros2 node list --no-daemon` 无导航相关节点残留。
6. 让机器人进入安全状态。
7. 关闭机器人本体和遥控器。
8. 充电或整理设备。
9. 如运行中出现异常，记录时间、点位、现象和现场环境。

## 10. 常见故障处理

### 10.1 APP 连接不上

可能原因：

- APP 和机器人主机不在同一网络。
- APP 连接 IP 或端口错误。
- WebSocket 服务未启动。
- 防火墙或网络策略限制连接。

处理：

1. 确认机器人主机 IP。
2. 确认 `./start_navigation.sh` 已启动。
3. 检查 APP 连接地址。
4. 必要时联系现场技术人员检查 WebSocket 服务。

### 10.2 机器人不动

可能原因：

- 机器人未进入行走控制状态。
- 导航任务未成功下发。
- `/cmd_vel` 无输出。
- WebSocket 客户端未连接到底层控制服务。
- 急停未释放或底层报警。

处理：

1. 检查机器人是否站稳并可用遥控器短距离移动。
2. 检查 APP 是否收到导航命令结果。
3. 检查急停和底层报警。
4. 技术人员可按附录检查 `/cmd_vel` 和 WebSocket 节点。

### 10.3 机器人路径偏离或定位异常

可能原因：

- 当前环境与地图不一致。
- 雷达被遮挡。
- 机器人启动位置与地图差异过大。
- 地图质量不佳或存在重影。
- 机器人被人工移动后未重新定位。
- 展厅内新增大型展架、围挡、玻璃反射区域或人员密集遮挡。

处理：

1. 停止导航。
2. 清理环境并检查雷达。
3. 将机器人放回已知起点或明显地标附近。
4. 观察 APP 中实时位姿是否恢复稳定。
5. 如仍异常，由技术人员打开 RViz，检查 `/map`、机器人模型和 TF 是否正常。
6. 在停止导航状态下，可使用 RViz `2D Pose Estimate` 手动设置初始位姿。
7. 重新下发短路线多点导航测试，确认稳定后再恢复正式导览。
8. 如仍异常，重新建图或联系技术人员处理定位参数。

禁止：定位异常时不得继续执行正式导览任务，也不得在 APP 多点导航执行中使用 RViz 手动目标点。

### 10.4 建图 RViz 没有地图或点云

可能原因：

- 雷达无数据。
- Fast-LIO 未运行。
- 地图文件未加载。
- ROS 环境未加载。

处理：

1. 检查雷达供电和网线。
2. 重启建图 launch。
3. 技术人员按附录检查 `/airy_points`、`/fast_lio/cloud_registered`、`/map`。

### 10.5 机器人无法到达点位

可能原因：

- 点位设置在障碍区、墙边或膨胀区。
- 通道被临时障碍物阻挡。
- 目标点朝向不合理，转身空间不足。

处理：

1. 停止当前任务。
2. 清理通道障碍。
3. 在 APP 中调整点位位置和朝向。
4. 将调整后的点位加入多点导航测试路线，确认可达后再恢复正式多点导航。

### 10.6 充电异常

可能原因：

- 充电器型号不匹配。
- 接口未插紧。
- 电池或充电器过热。
- 电池损坏或保护。

处理：

1. 停止使用并断开充电器。
2. 检查充电器、电池和接口。
3. 更换原厂指定充电器或电池测试。
4. 如有发热、异味、鼓包或冒烟，不得继续使用。

### 10.7 直流供电异常

可能原因：

- 电源规格不匹配。
- 接口松动。
- 线缆被拉扯或压迫。
- 供电设备过载保护。

处理：

1. 停止机器人运动。
2. 关闭直流电源。
3. 检查线缆、接口和电源指示灯。
4. 按现场交付资料确认规格。
5. 未确认原因前不得恢复行走。

### 11.6 巡航速度参数位置

```text
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/config/nav2_params.yaml
```

主要调整项：

```yaml
controller_server:
  ros__parameters:
    FollowPath:
      desired_linear_vel: 0.5
      max_linear_accel: 0.35
      max_linear_decel: 0.35
      min_approach_linear_velocity: 0.20
```

说明：

- `desired_linear_vel`：期望巡航线速度，是日常调速的主要入口。
- `max_linear_accel`、`max_linear_decel`：限制起步和减速变化。
- `min_approach_linear_velocity`：接近目标点时的最低线速度，不能低于机器人有效起步速度。

修改后必须重启 `./start_navigation.sh`，并通过 APP 多点导航完成测试。

## 12. 附录：APP 交互接口与数据链

本附录根据《功能指令库》整理。当前客户导览导航只使用多点导航；单点导航、展台导航、重试失败点、跳过目标点和设置初始位姿属于接口能力或预留接口，当前现场流程暂不使用。

### 12.1 总体链路

APP 与 ROS 通过 WebSocket 通信，主要数据链如下：

```text
APP
  -> websocket_server
  -> /app/waypoint_command 或 /app/navigation_command 或 /app/robot_control 或 /robot/facial_raw_cmd 或 /initialpose
  -> dynamic_waypoints_manager / navigation_state_manager / websocket_client / facial_driver / 定位节点
  -> Nav2、机器人底层、表情模块
  -> /navigation/status、/navigation/acknowledgments、/navigation/waypoints_data、/robot_realpose、/robot_speed、/robot/action_result
  -> data_integration_node
  -> websocket_server
  -> APP
```

主要节点职责：

- `websocket_server`：接收 APP WebSocket 消息，返回连接、订阅和命令即时应答，并把命令转成 ROS 话题。
- `dynamic_waypoints_manager`：处理点位新增、更新、删除、查询和点位数据发布。
- `navigation_state_manager`：处理多点导航、暂停、停止、导航状态和 Nav2 action。
- `data_integration_node`：汇总定位、速度、导航、系统、点位、动作结果等数据并推送给 APP。
- `websocket_client`：连接机器人底层 WebSocket，转发 `/cmd_vel`、动作控制和底层状态。
- `message_bridge`：将底层原始状态、IMU、关节等数据桥接为 ROS 标准或系统内部话题。
- `facial_driver`：订阅 `/robot/facial_raw_cmd` 并控制头部表情模块。

### 12.2 消息通用结构

APP 消息使用统一 JSON 结构：

```json
{
  "protocol_version": "2.0",
  "message_id": "唯一消息ID",
  "timestamp": 1712345678.0,
  "message_type": "request | response | push | subscription | command",
  "data_type": "业务数据类型",
  "source": "app",
  "destination": "ros",
  "data": {},
  "metadata": {
    "status": "pending",
    "error_code": "",
    "error_message": "",
    "request_id": "",
    "data_freshness": 0.0,
    "qos_level": "standard"
  }
}
```

### 12.3 连接与订阅

| 功能 | 方向 | message_type | data_type | 涉及节点 | 数据链 |
|---|---|---|---|---|---|
| 连接 ROS 端 | APP -> ROS | WebSocket 连接 | connection_ack | `websocket_server` | APP 建连后，服务端返回 `client_id`、支持的数据类型、支持的命令和心跳间隔。 |
| 订阅数据 | APP -> ROS | `subscription` | `subscription_manage` | `websocket_server`、`data_integration_node` | APP 订阅 `robot_pose`、`robot_speed`、`navigation_status`、`navigation_path`、`system_status`、`waypoints_data`、`action_result` 后，数据整合节点按频率推送。 |

订阅示例：

```json
{
  "protocol_version": "2.0",
  "message_id": "subscription_001",
  "timestamp": 1712345678.0,
  "message_type": "subscription",
  "data_type": "subscription_manage",
  "source": "app",
  "destination": "ros",
  "data": {
    "action": "subscribe",
    "data_types": [
      "robot_pose",
      "robot_speed",

      "navigation_path",

  }
```

### 12.4 数据查询接口

| 功能 | 方向 | message_type | data_type | 涉及节点 | 数据链 |
|---|---|---|---|---|---|
| 获取实时定位 | APP -> ROS | `request` | `robot_pose` | `websocket_server`、`data_integration_node` | APP 请求后，数据整合节点返回 `/robot_realpose` 整理后的地图坐标、朝向、定位质量和置信度。 |
| 获取导航状态 | APP -> ROS | `request` | `navigation_status` | `websocket_server`、`data_integration_node`、`navigation_state_manager` | 返回当前状态、导航模式、当前点位索引、总点位数、进度、恢复状态和性能统计。 |
| 获取路径规划数据 | APP -> ROS | `request` | `navigation_path` | `websocket_server`、`data_integration_node`、Nav2 | 返回全局路径或局部路径数据，用于 APP 显示。 |
| 获取动作库列表 | APP -> ROS | `request` | `gesture_list` | `websocket_server`、`data_integration_node`、`websocket_client` | 从机器人底层或本地 YAML 获取可执行动作列表。 |
| 获取表情库列表 | APP -> ROS | `request` | `facial_gesture_list` | `websocket_server`、`data_integration_node` | 从表情配置中返回可执行表情列表。 |

### 12.5 点位管理接口

| 功能 | command_type | 涉及节点 | 数据链 |
|---|---|---|---|
| 设置点位 | `set_waypoint` | `websocket_server`、`dynamic_waypoints_manager` | APP -> `/app/waypoint_command` -> 点位管理节点保存点位 -> `/navigation/waypoints_data` -> 数据整合 -> APP。 |
| 更新点位 | `update_waypoint` | `websocket_server`、`dynamic_waypoints_manager` | 与设置点位相同，按点位 `id` 更新位置、朝向、类型和属性。 |
| 删除点位 | `delete_waypoint` | `websocket_server`、`dynamic_waypoints_manager` | 删除指定点位后推送完整点位数据。 |
| 获取点位列表 | `get_waypoints` | `websocket_server`、`dynamic_waypoints_manager` | 返回全部或指定类型点位。 |
| 清空点位 | `clear_waypoints` | `websocket_server`、`dynamic_waypoints_manager` | 清空点位数据，客户现场慎用。 |

点位设置示例：

```json
{
  "protocol_version": "2.0",
  "message_id": "cmd_set_wp_001",
  "timestamp": 1712345678.0,
  "message_type": "command",
  "data_type": "waypoint_management",
  "source": "app",
  "destination": "ros",
  "data": {
    "command_type": "set_waypoint",
    "waypoint_data": {
      "id": "wp_001",
      "name": "展台1",
      "type": "exhibition_point",
      "position": [2.0, 3.0, 0.0],
      "orientation": [0.0, 0.0, 0.0, 1.0],
      "frame_id": "map",
      "properties": {
        "stay_time": 10.0,
        "walk_direction": "forward",
        "description": "第一个展台讲解点"
      }
    }
  },
  "metadata": {
    "qos_level": "standard"
  }
}
```

说明：

- `type` 必须使用系统支持的点位类型，例如 `navigation_target`、`exhibition_point`、`charging_point`、`rest_point`、`landmark_point`、`obstacle_point`。
- `walk_direction` 可用于标记特殊行走方向，默认正向行走时可不填或填 `forward`。

### 12.6 导航控制接口

当前现场使用的导航命令只有多点导航。

| 功能 | 使用状态 | command_type | 涉及节点 | 数据链 |
|---|---|---|---|---|
| 多点导航 | 当前使用 | `start_multi_point_navigation` | `websocket_server`、`dynamic_waypoints_manager`、`navigation_state_manager`、Nav2 | APP -> `/app/navigation_command` -> 点位管理节点校验点位 -> 状态管理节点逐点调用 Nav2 -> `/cmd_vel` -> 机器人底层。 |
| 停止导航 | 当前使用 | `stop_navigation` | `websocket_server`、`navigation_state_manager`、Nav2 | APP -> `/app/navigation_command` -> 状态管理节点取消当前 Nav2 action 并发布状态。 |
| 暂停导航 | 可用接口 | `pause_navigation` | `websocket_server`、`navigation_state_manager` | APP -> `/app/navigation_command` -> 状态管理节点暂停任务。 |
| 单点导航 | 暂不使用 | `start_single_navigation` | 同导航链路 | 保留能力，当前客户流程不使用。 |
| 展台导航 | 暂不使用 | `start_exhibition_navigation` | 同导航链路 | 保留能力，当前客户流程不使用。 |
| 重试失败点 | 预留接口 | `retry_failed_waypoint` | `navigation_state_manager` | 当前暂不使用，仅保留给失败恢复流程扩展。 |
| 跳过目标点 | 预留接口 | `skip_failed_waypoint` | `navigation_state_manager` | 当前暂不使用，仅保留给失败恢复流程扩展。 |

多点导航示例：

```json
{
  "protocol_version": "2.0",
  "message_id": "cmd_multi_nav_001",
  "timestamp": 1712345678.0,
  "message_type": "command",
  "data_type": "navigation_control",
  "source": "app",
  "destination": "ros",
  "data": {
    "command_type": "start_multi_point_navigation",
    "waypoint_ids": ["wp_001", "wp_002", "wp_003"],
    "sequence_name": "多点导航序列1",
    "navigation_parameters": {
      "loop_enabled": false,
      "stop_at_each_point": true,
      "stop_duration": 5.0,
      "continue_on_failure": false
    }
  },
  "metadata": {
    "qos_level": "standard"
  }
}
```

停止导航示例：

```json
{
  "protocol_version": "2.0",
  "message_id": "cmd_stop_nav_001",
  "timestamp": 1712345678.0,
  "message_type": "command",
  "data_type": "navigation_control",
  "source": "app",
  "destination": "ros",
  "data": {
    "command_type": "stop_navigation",
    "stop_parameters": {
      "emergency_stop": false,
      "preserve_state": true,
      "reason": "user_request"
    }
  },
  "metadata": {
    "qos_level": "realtime"
  }
}
```

注意：APP 的 `stop_navigation` 是软件停止导航，不等同于机器人本体急停。机器人急停会导致关节失能瘫倒，必须按本文急停要求处理。

### 12.7 动作与表情接口

| 功能 | data_type | 涉及节点 | 数据链 |
|---|---|---|---|
| 执行动作 | `robot_control` | `websocket_server`、`websocket_client`、机器人底层 | APP -> `/app/robot_control` -> 底层 WebSocket -> 机器人执行动作 -> `/robot/action_result` -> APP。 |
| 执行表情 | `facial_control` | `websocket_server`、`facial_driver` | APP -> `/robot/facial_raw_cmd` -> 表情控制串口 -> 表情模块。 |
| 动作完成推送 | `action_result` | `websocket_client`、`data_integration_node` | 底层动作完成 -> ROS 推送动作结果 -> APP。 |

### 12.8 状态推送接口

| 推送内容 | data_type | 来源节点 | 主要字段 |
|---|---|---|---|
| 导航状态 | `navigation_status` | `navigation_state_manager`、`data_integration_node` | `current_state`、`navigation_mode`、`current_waypoint_index`、`total_waypoints`、`progress_percentage`、`recovery_active`。 |
| 到达路点 | `navigation_event` | `navigation_state_manager` | `event_type=waypoint_reached`、点位信息、当前序号、总点位数、停留时间。 |
| 导航完成 | `navigation_event` | `navigation_state_manager` | `event_type=navigation_completed`、总耗时、完成点位数、成功率。 |
| 导航命令结果 | `navigation_command_result` | `navigation_state_manager`、`data_integration_node` | 命令成功、失败、可恢复失败、失败点位索引、可用动作等。 |
| 系统状态 | `system_status` | `message_bridge`、`data_integration_node` | 电量、信号、网络延迟、机器人状态、急停状态、电机状态、跌倒状态。 |
| 实时定位 | `robot_pose` | `robot_realpose_publisher`、`data_integration_node` | `position`、`orientation`、`pose_quality`、`location_confidence`、速度。 |
| 当前速度 | `robot_speed` | `message_bridge` 或运动状态节点 | 线速度、角速度和运动状态。 |
| 路径规划 | `navigation_path` | Nav2、`data_integration_node` | 全局路径、局部路径、路径安全状态。 |

### 12.9 预留接口说明

以下接口当前暂不作为客户现场操作流程使用：

- `initial_pose`：设置初始位姿，预留给定位初始化或人工重定位场景。
- `retry_failed_waypoint`：重试失败点，预留给导航失败恢复流程。
- `skip_failed_waypoint`：跳过当前目标点，预留给导航失败恢复流程。
- `start_single_navigation`：单点导航，当前不作为正式导览流程。
- `start_exhibition_navigation`：展台导航，当前不作为正式导览流程。

如需启用上述接口，应先由现场技术人员完成联调和验收，再开放给 APP 正式使用。

## 13. 交付验收建议

交付时建议按以下顺序验收：

1. 遥控器连接正常，急停风险和吊架防护要求已向客户说明。
2. 机器人可按顺序进入零力矩、阻尼、站着和行走控制状态。
3. 机器人可用遥控器完成短距离前进、后退和转向。
4. 建图系统可启动，RViz 有点云和地图显示。
5. 地图保存流程可完成，关键文件存在。
6. 导航系统可通过 `./start_navigation.sh` 启动。
7. APP 可连接 WebSocket 服务并订阅状态。
8. APP 可设置点位，并完成多点导航。
9. APP 可接收导航状态、定位、速度、系统状态和动作结果推送。
10. 充电、电池更换或直流供电流程已向客户说明。

交付完成后，建议客户保留：

- 本说明书。
- 原厂硬件说明书。
- 现场地图文件和点位配置。
- 机器人、电池、充电器、直流电源的型号和铭牌照片。
- 售后联系人和问题记录模板。
