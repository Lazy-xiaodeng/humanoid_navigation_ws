## 1. 当前默认系统链路

当前一键启动入口是：

```bash
ros2 launch humanoid_bringup robot_real.launch.py
```

默认 `relocalization_engine:=ro`，也就是 RoboSense 全局定位链路。主要启动顺序如下：

1. `humanoid_description/display.launch.py`：启动机器人描述和 TF 基础信息。
2. `humanoid_navigation2/navigation2_robosense_lidar.launch.py`：启动雷达、Fast-LIO、RoboSense 定位、map->odom 桥接、Nav2。
3. `humanoid_navigation/navigation_fusion_sc.launch.py`：启动动态点位管理和导航状态管理。
4. `humanoid_websocket/websocket_server.launch.py`：启动 APP WebSocket 服务、数据整合、机器人本体客户端和消息桥。
5. `humanoid_locomotion/locomotion.launch.py`：启动动作/表情相关节点。
6. 可选启动 RViz：`rviz:=true` 时加载 `humanoid_navigation2/rviz/navigation.rviz`。

整体数据流：

```text
RoboSense 雷达/IMU
  -> rslidar_sdk_node
  -> fastlio_mapping
  -> robosense_lidar_localization_node
  -> prior_map_odom_bridge
  -> map->odom / map_ground / odom_ground
  -> Nav2 planner/controller/behavior/bt_navigator
  -> navigation_state_manager
  -> data_integration_node + websocket_server
  -> APP
```

APP 控制流：

```text
APP WebSocket command
  -> websocket_server
  -> /app/waypoint_command 或 /app/navigation_command
  -> dynamic_waypoints_manager
  -> /navigation/requests
  -> navigation_state_manager
  -> Nav2 NavigateToPose action
```

## 5. 导航应用层节点

### 5.1 `dynamic_waypoints_manager`

包：`humanoid_navigation`  
职责：点位数据管理和导航请求转发，不直接执行导航。

实现功能：

- 管理点位类型：`navigation_target`、`exhibition_point`、`obstacle_point`、`charging_point`、`rest_point`、`landmark_point`。
- 支持 APP 点位命令：`set_waypoint`、`update_waypoint`、`delete_waypoint`、`get_waypoints`、`clear_waypoints`。
- 支持导航请求校验和转发：`start_single_navigation`、`start_multi_point_navigation`、`start_exhibition_navigation`。
- 点位数据持久化到 `/home/ubuntu/humanoid_ws/data/dynamic_waypoints.json`。
- 发布完整点位数据给 WebSocket 和导航状态管理器。
- 点位 `properties` 支持速度字段：`speed`、`target_speed`、`navigation_speed`，会统一规范为 `properties.speed`，合法范围 `0.15~1.00 m/s`。
- 点位 `properties.walk_direction` 支持 `backward/reverse/back/倒走/倒车/后退`，由状态管理器切换倒走行为树。

主要话题：

| 方向 | 话题 | 说明 |
| --- | --- | --- |
| 订阅 | `/app/waypoint_command` | APP 点位管理命令 |
| 订阅 | `/app/navigation_command` | APP 导航控制命令 |
| 订阅 | `/navigation/acknowledgments` | 导航状态管理器返回的确认 |
| 发布 | `/navigation/requests` | 转发给状态管理器的导航请求 |
| 发布 | `/navigation/waypoints_data` | 点位全量/增量数据 |

### 5.2 `navigation_state_manager`

包：`humanoid_navigation`  
职责：实际执行导航、管理状态、处理暂停/继续/终止/失败恢复、向 APP 推送导航状态。

实现功能：

- 接收 `/navigation/requests`，执行单点、多点、展台巡航导航。
- 调用 Nav2 `NavigateToPose` action 发送目标。
- 支持导航控制命令：
  - `start_single_navigation`
  - `start_multi_point_navigation`
  - `start_exhibition_navigation`
  - `pause_navigation`
  - `resume_navigation`
  - `stop_navigation`
  - `retry_failed_waypoint`
  - `skip_failed_waypoint`
  - `abort_failed_navigation`
- 发布导航状态：空闲、规划中、执行中、暂停、到点、完成、失败、可恢复失败、取消等。
- 发布导航进度：当前点位、总点位数、当前索引、剩余距离、当前速度、耗时、跳过点列表。
- 根据机器人状态判断是否允许启动导航。默认要求机器人处于可行走状态。
- 检测障碍阻塞：导航执行中速度低于阈值并超过 `obstacle_block_timeout` 后，推送 `navigation_obstacle_blocked`，但默认不取消 Nav2 目标。
- 定位恢复联动：可根据 `/localization/recovery_status` 或 `/localization/prior_map_odom_bridge_status` 自动暂停、等待恢复、自动继续导航。
- 定位恢复期间拒绝 APP 手动 `resume_navigation`，避免覆盖自动保护逻辑。
- 支持失败点重试和跳过：`retry_failed_waypoint`、`skip_failed_waypoint`。
- 支持倒走点：如果点位要求倒走，给 `NavigateToPose` 设置 `navigate_reverse_xy_then_yaw.xml` 行为树。

主要话题：

| 方向 | 话题 | 说明 |
| --- | --- | --- |
| 订阅 | `/navigation/requests` | 点位管理器转发的导航请求 |
| 订阅 | `/navigation/waypoints_data` | 当前点位数据库 |
| 订阅 | `/odom` | 位姿、速度、阻塞检测 |
| 订阅 | `/robot_status_processed` | 机器人动作/控制状态 |
| 订阅 | `/behavior_tree_log` | 识别 Spin/BackUp 等行为树阶段，抑制阻塞误报 |
| 订阅 | `/localization/prior_map_odom_bridge_status` | 定位健康状态 |
| 订阅 | `/localization/recovery_status` | 重定位状态 |
| 发布 | `/navigation/status` | 导航状态和事件 |
| 发布 | `/navigation/acknowledgments` | 导航命令确认/错误 |
| 发布 | `/localization/recovery_requests` | 可选触发重定位请求 |

## 6. WebSocket 与 APP 交互节点

### 6.1 `websocket_server`

包：`humanoid_websocket`  
职责：作为 APP 的 WebSocket 服务端，负责连接管理、协议封装、命令路由和推送转发。

实现功能：

- 启动 WebSocket 服务。`websocket_config.yaml` 默认端口 `8765`，`robot_config.yaml` 中实机配置端口 `5000`、host `10.192.1.2`。
- APP 连接后返回 `connection_ack`，包含 `client_id`、支持的数据类型和命令类型。
- 支持消息类型：`request`、`response`、`push`、`subscription`、`command`。
- 支持 APP 订阅数据类型，例如：
  - `robot_pose`
  - `robot_speed`
  - `navigation_path`
  - `navigation_status`
  - `system_status`
  - `waypoints_data`
  - `action_result`
  - `facial_gesture_list`
- 路由业务命令：
  - `waypoint_management` -> `/app/waypoint_command`
  - `navigation_control` -> `/app/navigation_command`
  - `robot_control` -> `/app/robot_control`
  - `facial_control` -> `/robot/facial_raw_cmd`
  - `initial_pose` -> `/initialpose`
- 接收 `/integration/data_responses`、`/integration/push_messages`、`/integration/subscription_responses` 并转发给 APP。
- APP 设置初始位姿时，将 `x/y/yaw/frame_id` 转换为 `PoseWithCovarianceStamped` 发布到 `/initialpose`，等价于 RViz 的 2D Pose Estimate。
- 表情控制时，将 action 字符串转发到 `/robot/facial_raw_cmd`，并返回 `command_ack`。

主要话题：

| 方向 | 话题 | 说明 |
| --- | --- | --- |
| 发布 | `/app/waypoint_command` | 点位管理命令 |
| 发布 | `/app/navigation_command` | 导航控制命令 |
| 发布 | `/app/robot_control` | 动作/机器人控制命令 |
| 发布 | `/app/system_command` | 系统管理命令 |
| 发布 | `/robot/facial_raw_cmd` | 面部表情命令 |
| 发布 | `/initialpose` | 初始位姿 |
| 发布 | `/websocket/data_requests` | 数据请求 |
| 发布 | `/websocket/data_subscriptions` | 订阅管理 |
| 订阅 | `/navigation/waypoints_data` | 点位更新 |
| 订阅 | `/navigation/sequences` | 导航序列更新 |
| 订阅 | `/integration/data_responses` | 数据整合节点响应 |
| 订阅 | `/integration/push_messages` | 主动推送 |
| 订阅 | `/integration/subscription_responses` | 订阅响应 |

### 6.2 `data_integration_node_recoverable`

包：`humanoid_websocket`  
职责：整合 ROS 侧实时数据，按 APP 协议响应请求和主动推送。

实现功能：

- 聚合导航状态、路径、位姿、速度、系统状态、点位数据、动作结果、表情库等。
- 响应 WebSocket 数据请求并发布到 `/integration/data_responses`。
- 根据 APP 订阅频率发布周期性推送到 `/integration/push_messages`。
- 将导航异常、定位异常、动作完成/超时等事件包装成 APP 可消费的 push 消息。

### 6.3 `message_bridge`

包：`humanoid_websocket`  
职责：机器人本体原始消息和 ROS 标准消息之间的桥接。

实现功能：

- 订阅 `/robot_status_raw`，解析机器人状态、电量、急停、信号等字段。
- 发布 `/robot_status_processed`，供 APP 和导航状态管理器判断机器人是否可导航。
- 订阅原始 IMU 和关节数据，发布 `/imu`、`/joint_states`。

### 6.4 `websocket_client`

包：`humanoid_websocket`  
职责：连接机器人本体或外部服务的 WebSocket 客户端。当前由 `websocket_server.launch.py` 一起启动。

### 6.5 `synthetic_data_publisher` / `omni_teleop_keyboard`

包：`humanoid_websocket`  
职责：调试辅助。前者发布模拟位姿、odom、路径、导航状态和系统状态；后者通过键盘发布 `/cmd_vel`。

| 功能 | data_type/message_type | 说明 |

### 8.2 点位管理

| 功能 | command_type | 说明 |
| --- | --- | --- |
| 设置点位 | `set_waypoint` | 新增点位，字段包含 id/name/type/position/orientation/frame_id/properties。 |
| 更新点位 | `update_waypoint` | 更新已有点位。 |
| 删除点位 | `delete_waypoint` | 删除指定点位，并从导航序列中移除。 |
| 获取点位列表 | `get_waypoints` | 支持按类型或 all 获取。 |
| 清空点位 | `clear_waypoints` | 清空指定类型或全部点位。 |

点位扩展字段：

- `properties.stay_time`：展点停留时间。
- `properties.walk_direction`：`forward` 或 `backward`，倒走点会使用倒走行为树。
- `properties.speed` / `target_speed` / `navigation_speed`：点位期望速度，合法范围 `0.15~1.00 m/s`。
- `properties.description`：点位描述。
- `properties.color`：APP/RViz 展示颜色。

### 8.3 导航控制

| 功能 | command_type | 说明 |
| --- | --- | --- |
| 单点导航 | `start_single_navigation` | 传入 `waypoint_id`。 |
| 多点导航 | `start_multi_point_navigation` | 传入 `waypoint_ids`。 |
| 展台巡航 | `start_exhibition_navigation` | 使用已配置的 `exhibition_point` 点位。 |
| 暂停导航 | `pause_navigation` | 取消当前 Nav2 目标，保存当前点位和进度。 |
| 继续导航 | `resume_navigation` | 从当前未完成点位继续。定位恢复中会拒绝手动恢复。 |
| 终止导航 | `stop_navigation` | 取消当前导航并重置状态。 |
| 重试失败点 | `retry_failed_waypoint` | 导航失败进入可恢复状态后，重新尝试当前失败点。 |
| 跳过失败点 | `skip_failed_waypoint` | 跳过当前失败点，继续后续点位。 |
| 终止失败导航 | `abort_failed_navigation` | 放弃可恢复失败状态。 |

## 11. 当前功能边界说明

- 当前默认实机链路是 `ro/robosense`，旧 `prior/sc/hdl` 链路仍保留为 launch 参数回退入口，但不是默认一键启动路径。
- `navigation_state_manager` 是当前 APP 导航控制的核心节点；`dynamic_waypoints_manager` 只管理点位和转发请求。
- 普通导航禁止倒车；只有点位明确设置倒走或定位恢复后选中倒走续航时，才使用倒走行为树。
- 障碍阻塞上报不会默认终止 Nav2，APP 收到异常后可提示用户处理，也可再发暂停/终止命令。
- `nav2_params.yaml` 中 `behavior_server` 当前只加载 `spin` 和 `wait`；虽然保留了 `backup` 参数块，但未启用。
- 点位级 `properties.speed` 已在点位管理器中校验和保存；若要真正动态改 Nav2 控制器速度，需要确认状态管理器对应的参数下发逻辑是否在当前入口中启用。
