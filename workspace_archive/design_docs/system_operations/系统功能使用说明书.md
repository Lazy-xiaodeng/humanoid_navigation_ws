# 人形机器人建图导航系统功能使用说明书

版本日期：2026-05-21
工作空间：`/home/ubuntu/humanoid_ws`
适用对象：首次使用本系统的客户、现场交付人员、售后调试人员

本文说明从开机、打开终端、编译工作空间、启动功能节点，到完成建图、保存地图、启动导航、APP 交互控制和常见故障排查的完整流程。

## 1. 使用前准备

### 1.1 基本要求

使用前请确认：

- 机器人本体已上电，雷达、IMU、头部表情模块、机器人底层控制服务正常供电。
- 工控机或主机已进入 Ubuntu 桌面。
- 当前工作空间路径为：`/home/ubuntu/humanoid_ws`
- ROS 2 版本为 Jazzy，环境文件路径为：`/opt/ros/jazzy/setup.bash`
- 工作空间已经编译生成：`/home/ubuntu/humanoid_ws/install/setup.bash`
- 机器人和 APP 所在设备处于同一网络，APP 能访问 ROS 端 WebSocket 地址。

### 1.2 终端基本操作

打开终端：

1. 在 Ubuntu 桌面按 `Ctrl + Alt + T` 打开一个终端。
2. 每开一个新终端，都先进入工作空间并加载环境：

```bash
cd /home/ubuntu/humanoid_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
```

如果使用本文提供的一键脚本 `./start_navigation.sh`，脚本内部会自动加载环境；但手动运行 `ros2 launch`、`ros2 topic`、`ros2 service` 时，仍建议先执行上面三行。

### 1.3 编译工作空间

首次部署、修改代码、修改 launch 或新增脚本后，需要重新编译：

```bash
cd /home/ubuntu/humanoid_ws
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
```

编译完成后，如果没有报错，说明功能包已安装到 `install/` 目录。

## 2. 系统整体架构

系统主要由以下链路组成：

```text
雷达/IMU
  -> rslidar_sdk
  -> Fast-LIO
  -> 点云滤波 / 清障点云
  -> 建图或定位
  -> Nav2 导航栈
  -> /cmd_vel
  -> WebSocket 客户端
  -> 机器人底层行走控制

APP
  -> WebSocket 服务端
  -> 点位管理 / 导航状态管理 / 动作表情控制
  -> ROS 话题与 Nav2
```

当前实机正式导航主入口是：

```bash
/home/ubuntu/humanoid_ws/start_navigation.sh
```

该脚本实际启动：

```bash
ros2 launch humanoid_bringup robot_real.launch.py use_sim_time:=false
```

`robot_real.launch.py` 会按顺序自动拉起：

1. 机器人模型与 TF 基础节点。
2. 导航栈 `humanoid_navigation2/launch/navigation_stack.launch.py`。
3. 应用层节点：点位管理、导航状态管理、WebSocket、表情控制。
4. RViz 可视化界面。

## 3. 功能节点说明

### 3.1 机器人描述节点

功能作用：

- 加载机器人 URDF/Xacro 模型。
- 发布机器人基础 TF。
- 给 RViz 显示机器人模型提供数据。

启动命令：

```bash
ros2 launch humanoid_description display.launch.py rviz:=false
```

常用说明：

- 正式启动时不需要单独运行，`robot_real.launch.py` 会自动启动。
- 单独调试模型时可设置 `rviz:=true` 打开 RViz。

检查方法：

```bash
ros2 node list | grep robot_state_publisher
ros2 topic echo /tf_static --once
```

常见故障：

- RViz 中看不到机器人模型：检查 `robot_state_publisher` 是否运行。
- TF 报错：检查 `display.launch.py` 是否成功加载 URDF。

### 3.2 雷达驱动节点 `rslidar_sdk_node`

功能作用：

- 连接 Robosense 雷达。
- 发布原始点云 `/airy_points`。
- 为 Fast-LIO 提供点云输入。

正式导航中由 `navigation_stack.launch.py` 自动启动。

单独检查命令：

```bash
ros2 node list | grep rslidar_sdk_node
ros2 topic hz /airy_points
```

正常现象：

- `/airy_points` 有稳定频率。
- RViz 中点云随环境变化。

常见故障：

- `/airy_points` 没有数据：检查雷达供电、网线、IP 配置和雷达驱动。
- 点云频率很低：检查网络、CPU 占用和 FastDDS 共享内存配置。

### 3.3 Fast-LIO 节点 `fast_lio_node`

功能作用：

- 融合雷达和 IMU。
- 发布里程计 `/odom`。
- 发布配准后的点云 `/fast_lio/cloud_registered`。
- 建图时可保存 PCD 点云地图。

核心话题：

- 输入：`/airy_points`、`/airy_imu`
- 输出：`/odom`、`/fast_lio/cloud_registered`

检查命令：

```bash
ros2 node list | grep fast_lio_node
ros2 topic hz /odom
ros2 topic hz /fast_lio/cloud_registered
```

常见故障：

- `/odom` 无数据：检查雷达和 IMU 是否都有数据。
- 地图漂移严重：检查 IMU 时间戳、雷达安装外参、机器人是否剧烈晃动。
- 点云和机器人模型错位：检查 TF 树和 `odom -> camera_init -> body -> base_footprint` 是否完整。

### 3.4 建图核心节点 `robot_mapping.launch.py`

功能作用：

- 启动建图所需的雷达、Fast-LIO、TF、点云转激光和 `slam_toolbox`。
- 生成 3D PCD 地图和 2D 栅格地图。
- 打开建图 RViz 界面，便于观察地图生成效果。

启动命令：

```bash
ros2 launch humanoid_bringup robot_mapping.launch.py 2>&1 | tee debug_output-mapping.txt
```

内部包含：

- `humanoid_navigation2/launch/mapping_only.launch.py`
- `humanoid_websocket/launch/websocket_server.launch.py`
- `humanoid_locomotion/launch/locomotion.launch.py`
- `rviz2 -d mapping.rviz`

使用说明：

1. 启动后等待 10 到 20 秒，确认 RViz 中有点云和建图结果。
2. 建图时让机器人缓慢、平稳地走完整个环境。
3. 建图过程中不要快速旋转、撞墙、遮挡雷达。
4. 建图完成后按本文“保存地图流程”保存 PCD、2D 地图、posegraph 和 rosbag 数据库。

常见故障：

- RViz 没有地图：检查 `/scan`、`/map`、`/fast_lio/cloud_registered`。
- 地图重影：机器人走得太快、回环不稳定或雷达/IMU 时间不同步。
- 保存地图失败：检查 `slam_toolbox` 是否运行，路径目录是否存在。

### 3.5 PCD 保存器 `save_pcd_map.py`

功能作用：

- 建图时实时订阅 `/fast_lio/cloud_registered`。
- 累积全局点云。
- 按 `Ctrl+C` 退出时自动保存为 PCD 文件。

启动命令：

```bash
python3 /home/ubuntu/humanoid_ws/src/humanoid_navigation2/humanoid_navigation2/save_pcd_map.py \
  /home/ubuntu/humanoid_ws/src/humanoid_navigation2/pcd/hall.pcd
```

使用说明：

- 必须在建图过程中同步运行。
- 终端中会显示已累积帧数和点数。
- 建图完成后，在该终端按 `Ctrl+C`，等待提示 PCD 已保存后再关闭终端。

当前地图文件：

```text
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/pcd/hall.pcd
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/pcd/hall_standard.pcd
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/pcd/hall_localization_grounded.pcd
```

常见故障：

- 提示没有收集到点云：确认建图 launch 已启动，且 `/fast_lio/cloud_registered` 有数据。
- PCD 文件过大：属于正常现象；脚本会做体素降采样。

### 3.6 rosbag 录制

功能作用：

- 记录建图过程中的关键话题。
- 后续用于构建重定位数据库、复盘问题和离线调试。

推荐录制命令：

```bash
mkdir -p /home/ubuntu/fast-lio-bags

ros2 bag record -o /home/ubuntu/fast-lio-bags/hall_mapping \
  /fast_lio/cloud_registered \
  /fast_lio/odom \
  /odom \
  /tf \
  /tf_static \
  /airy_imu \
  /airy_points
```

注意：

- 原命令中数据库构建路径写过 `~/bags/hall_mapping`，而录制路径写的是 `~/fast-lio-bags/hall_mapping`。建议统一使用 `/home/ubuntu/fast-lio-bags/hall_mapping`，避免找不到 bag。
- 建图完成后，先在录包终端按 `Ctrl+C`，等待 rosbag 写入完成。

检查命令：

```bash
ros2 bag info /home/ubuntu/fast-lio-bags/hall_mapping
```

### 3.7 Scan Context 数据库构建

功能作用：

- 从建图 rosbag 中提取关键帧。
- 构建重定位使用的 Scan Context 数据库。

启动命令：

```bash
ros2 run humanoid_relocalization build_sc_database.py \
  --bag /home/ubuntu/fast-lio-bags/hall_mapping \
  --output /home/ubuntu/humanoid_ws/src/humanoid_navigation2/maps/hall_sc.bin \
  --cloud-topic /fast_lio/cloud_registered \
  --odom-topic /odom \
  --interval 2.0
```

输出文件：

```text
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/maps/hall_sc.bin
```

常见故障：

- 提示 bag 中没有指定话题：用 `ros2 bag info` 查看实际话题名。
- 构建结果为空：检查建图时 `/fast_lio/cloud_registered` 是否被录入。

### 3.8 2D 栅格地图保存

功能作用：

- 保存给 Nav2 `map_server` 使用的 2D 地图。
- 输出 `hall.yaml` 和 `hall.pgm`。

启动命令：

```bash
ros2 run nav2_map_server map_saver_cli \
  -f /home/ubuntu/humanoid_ws/src/humanoid_navigation2/maps/hall
```

输出文件：

```text
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/maps/hall.yaml
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/maps/hall.pgm
```

当前 `hall.yaml` 关键参数：

```yaml
image: hall.pgm
mode: trinary
resolution: 0.050
origin: [-6.648, -13.571, 0]
occupied_thresh: 0.65
free_thresh: 0.196
```

常见故障：

- 保存失败：检查 `/map` 是否有数据。
- 导航时地图不一致：确认保存的是最新环境，且 `navigation_stack.launch.py` 加载的是同一个 `hall.yaml`。

### 3.9 posegraph 保存

功能作用：

- 保存 `slam_toolbox` 的位姿图。
- 后续可用于继续建图、地图修正或回放分析。

启动命令：

```bash
ros2 service call /slam_toolbox/serialize_map \
  slam_toolbox/srv/SerializePoseGraph \
  "{filename: '/home/ubuntu/humanoid_ws/src/humanoid_navigation2/maps/hall'}"
```

输出文件通常为：

```text
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/maps/hall.posegraph
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/maps/hall.data
```

### 3.10 导航栈 `navigation_stack.launch.py`

功能作用：

- 启动实机导航底层完整链路。
- 包含传感器、Fast-LIO、点云滤波、地图服务、定位初始化、NDT 持续定位、Nav2 规划控制。

正式启动方式：

```bash
./start_navigation.sh
```

分层调试启动方式：

```bash
ros2 launch humanoid_navigation2 navigation_stack.launch.py use_sim_time:=false
```

主要内部节点：

- `rslidar_sdk_node`：雷达驱动。
- `fast_lio_node`：雷达惯性里程计。
- `point_cloud_filter_node`：点云滤波。
- `map_server`：加载 2D 地图。
- `hdl_global_localization` 和 `hdl_bootstrap_container`：启动阶段全局重定位。
- `hdl_bootstrap_to_initialpose`：把 bootstrap 结果发布到 `/initialpose`。
- `lidar_localization`：持续 NDT 定位并发布 `map -> odom`。
- `robot_realpose_publisher`：发布机器人真实地图位姿 `/robot_realpose`。
- `planner_server`：路径规划。
- `controller_server`：路径跟踪控制。
- `behavior_server`：旋转、等待等行为。
- `bt_navigator`：行为树导航。
- `periodic_clearing_publisher` 和 `periodic_clearing_3d_publisher`：辅助清障。

关键 TF：

```text
map -> map_ground
map -> odom
odom -> odom_ground
odom -> camera_init -> body -> base_footprint
base_footprint -> clearing_lidar
```

检查命令：

```bash
ros2 node list
ros2 topic list
ros2 topic echo /map --once
ros2 topic hz /robot_realpose
ros2 run tf2_ros tf2_echo map odom
ros2 lifecycle get /map_server
ros2 lifecycle get /bt_navigator
```

常见故障：

- `bt_navigator` 未启动：通常是定位 TF 未就绪，检查 `map_ground -> base_footprint`。
- `/cmd_vel` 无输出：检查 Nav2 是否激活、目标点是否可达、代价地图是否有障碍。
- 机器人不动但 `/cmd_vel` 有输出：检查机器人底层是否在 Walk 模式，WebSocket 客户端是否连接到底层。

### 3.11 点云滤波节点 `point_cloud_filter_node`

功能作用：

- 订阅 `/fast_lio/cloud_registered`。
- 去除机器人自身、雷达支架、地面噪点和离群点。
- 输出导航用点云 `/airy_points_filtered`。
- 输出高程图用点云 `/airy_points_for_elevation`。

启动命令：

```bash
ros2 launch humanoid_point_cloud_filter point_cloud_filter.launch.py
```

正式导航中由 `navigation_stack.launch.py` 自动启动。

检查命令：

```bash
ros2 topic hz /airy_points_filtered
ros2 topic echo /airy_points_filtered --once
```

常见故障：

- 机器人前方有障碍但 local costmap 不显示：检查 `/airy_points_filtered` 是否有点。
- 机器人身体被识别为障碍：调整 `point_cloud_filter_config.yaml` 中自身包络盒过滤范围。
- 地面被误识别为障碍：调整 `nav_min_z`、`nav_max_z`、高度连续性滤波参数。

### 3.12 Nav2 局部与全局代价地图

功能作用：

- 全局代价地图用于全局路径规划。
- 局部代价地图用于实时避障和路径跟踪。

当前主要配置文件：

```text
/home/ubuntu/humanoid_ws/src/humanoid_navigation2/config/nav2_params_xy_yaw.yaml
```

当前关键配置：

- 全局地图坐标系：`map_ground`
- 局部地图坐标系：`odom_ground`
- 机器人坐标系：`base_footprint`
- 分辨率：`0.05 m`
- 当前 local costmap 配置为 `width: 12`、`height: 12`
- 局部图层：`static_layer`、`voxel_layer`、`inflation_layer`
- 全局图层：`static_layer`、`obstacle_layer`、`inflation_layer`

RViz 中常见颜色说明：

- 灰色：自由空间，可通行。
- 黑色或深紫色：致命障碍。
- 粉色或紫色渐变：膨胀层代价区域。
- 青色：未知区域或部分清除区域。

常见故障：

- local costmap 一直有残影：检查清障点云、`clearing_lidar` TF、`periodic_clearing_3d_publisher`。
- 路径规划绕远：检查静态地图墙体、膨胀半径、目标点是否靠墙太近。
- 机器人不敢靠近目标：目标点可能落在膨胀区或障碍区内，重新选点。

### 3.13 点位管理节点 `dynamic_waypoints_manager`

功能作用：

- 接收 APP 的点位增删改查命令。
- 管理导航目标点、展台点、充电点、休息点、地标点等。
- 将点位数据发布到 `/navigation/waypoints_data`。
- 将导航命令转发给状态管理器。

启动命令：

```bash
ros2 launch humanoid_navigation navigation.launch.py
```

正式导航中由 `robot_real.launch.py` 自动启动。

支持的点位类型：

- `navigation_target`：普通导航目标点。
- `exhibition_point`：展台讲解点。
- `charging_point`：充电点。
- `rest_point`：休息点。
- `landmark_point`：地标点。
- `obstacle_point`：障碍标记点。

检查命令：

```bash
ros2 node list | grep dynamic_waypoints_manager
ros2 topic echo /navigation/waypoints_data
```

常见故障：

- APP 设置点位后不显示：检查 `/app/waypoint_command` 和 `/navigation/waypoints_data`。
- 多点导航提示点位不存在：确认 APP 传入的 `waypoint_id` 与已保存点位一致。

### 3.14 导航状态管理节点 `navigation_state_manager`

功能作用：

- 接收点位管理节点转发的导航请求。
- 调用 Nav2 `NavigateToPose` action。
- 发布导航状态 `/navigation/status`。
- 发布导航命令结果 `/navigation/acknowledgments`。
- 支持单点导航、多点导航、展台导航、停止、暂停、恢复、失败重试和跳过失败点。

正式导航中由 `humanoid_navigation/launch/navigation.launch.py` 自动启动。

检查命令：

```bash
ros2 node list | grep navigation_state_manager
ros2 topic echo /navigation/status
ros2 topic echo /navigation/acknowledgments
```

常见故障：

- 导航命令已发但没有执行：检查当前状态是否不是 `idle`，或者机器人底层是否未处于 Walk。
- 到达点后 APP 没有收到完成：检查 `/navigation/status` 和 `/integration/push_messages`。

### 3.15 WebSocket 服务端 `websocket_server`

功能作用：

- 给 APP 提供 WebSocket 连接入口。
- 接收 APP 请求、订阅和命令。
- 把 APP 命令转成 ROS 话题。
- 把 ROS 状态推送给 APP。

启动命令：

```bash
ros2 launch humanoid_websocket websocket_server.launch.py
```

正式导航中由 `robot_real.launch.py` 自动启动。

包含节点：

- `websocket_server_node`：APP 连接入口。
- `data_integration_node_recoverable`：数据整合和推送。
- `websocket_client_node`：连接机器人本体底层 WebSocket。
- `message_bridge_node`：原始数据转 ROS 标准消息。

检查命令：

```bash
ros2 node list | grep websocket
ros2 topic echo /integration/push_messages
```

连接地址：

- 以配置文件为准，服务端默认监听端口在代码中为 `8765`。
- 现场使用时请确认 APP 连接的 IP 是 ROS 主机 IP。

常见故障：

- APP 连接不上：检查 ROS 主机 IP、端口、防火墙和 WebSocket 服务是否启动。
- APP 能连接但没有数据：检查是否发送订阅请求，检查 `data_integration_node` 是否有对应数据源。
- 动作执行失败：检查 `websocket_client_node` 是否连接到机器人本体底层服务器。

### 3.16 WebSocket 客户端 `websocket_client_node`

功能作用：

- 连接机器人本体底层 WebSocket 服务。
- 将 ROS `/cmd_vel` 转换为底层行走指令。
- 接收机器人状态、电量、底层模式和动作完成通知。
- 执行上半身动作并发布 `/robot/action_result`。

关键话题：

- 订阅：`/cmd_vel`、`/app/robot_control`
- 发布：`/robot_status_raw`、`/robot/action_result`

常见故障：

- `/cmd_vel` 有数据但机器人不走：机器人底层可能不在 `Walk` 模式。
- 执行动作后无法导航：等待动作完成，确认 `control_ready_for_navigation: true`。
- WebSocket 客户端反复重连：检查机器人本体 IP、端口和网络。

### 3.17 消息桥接节点 `message_bridge_node`

功能作用：

- 把机器人本体原始 IMU、关节、状态数据转换为 ROS 标准话题。
- 发布 `/imu`、`/joint_states`、`/robot_status_processed`。

检查命令：

```bash
ros2 topic echo /robot_status_processed
ros2 topic echo /imu --once
ros2 topic echo /joint_states --once
```

常见故障：

- `surprised`：惊讶。
- `thinking1`、`thinking2`：思考。

## 6. 完整导航流程

本节适用于已有地图后，客户日常使用机器人导航。

### 6.1 开机到进入系统

1. 将机器人放到建图时的原点附近，也就是首次建图开始时机器人所在的位置。
2. 机器人朝向尽量与建图开始时一致，建议位置误差小于 `0.5 m`，朝向误差尽量小于 `15°`。
3. 打开机器人总电源。
4. 等待机器人本体控制系统启动完成。
5. 打开工控机或主机 Ubuntu 桌面。
6. 打开终端。
7. 确认工作空间存在：

```bash
cd /home/ubuntu/humanoid_ws
ls
```

注意：

- 当前建议从建图原点启动。虽然系统包含启动阶段重定位流程，但为了保证最高成功率，仍要求机器人每次开机后先放在建图原点附近。
- 开机后、定位完成前不要推动机器人，不要立即通过 APP 下发导航任务。
- 如果机器人不是从建图原点启动，可能出现 RViz 中机器人位置偏移、Nav2 长时间不激活或导航路径异常，此时需要回到建图原点重启，或用 RViz/APP 手动设置初始位姿。

### 6.2 终端 1：一键启动正式导航系统

```bash
cd /home/ubuntu/humanoid_ws
./start_navigation.sh
```

脚本会：

- 清空并重新写入 `debug_output.txt`。
- 加载 ROS 2 Jazzy 环境。
- 加载工作空间环境。
- 检查关键 Python 包。
- 启动 `robot_real.launch.py`。
- 自动打开 RViz。

启动后必须等待约 30 到 60 秒，直到定位和 Nav2 完成启动。等待期间不要点击 APP 导航按钮，也不要移动机器人。

### 6.3 启动后的定位等待流程

启动后的内部流程大致如下：

1. `0-10 秒`：系统加载 ROS 环境，启动机器人模型、雷达驱动、Fast-LIO、TF、地图服务和点云滤波节点。
2. `10-30 秒`：系统开始读取实时雷达点云和里程计，加载 2D 地图和 3D 定位地图，启动定位初始化流程。
3. `30-60 秒`：定位稳定后发布 `map -> odom`，`robot_realpose_publisher` 开始输出 `/robot_realpose`，随后 Nav2 的 `planner_server`、`controller_server`、`bt_navigator` 等节点激活。
4. `约 60 秒后`：RViz 中机器人位置、点云、地图和代价地图基本对齐，APP 能稳定获取定位和导航状态，此时再开始设置点位或下发导航任务。

客户现场判断“可以开始导航”的标准：

- RViz 中机器人模型在地图上的位置正确。
- 点云与地图墙体基本重合。
- APP 上能看到机器人实时位置。
- `/robot_realpose` 有稳定输出。
- `bt_navigator` 生命周期为 `active`。

可用以下命令辅助确认：

```bash
ros2 topic hz /robot_realpose
ros2 lifecycle get /bt_navigator
ros2 topic echo /navigation/status --once
```

如果 60 秒后仍未定位成功：

- 先确认机器人是否放在建图原点附近、朝向是否接近建图时方向。
- 检查雷达点云是否正常：`ros2 topic hz /fast_lio/cloud_registered`
- 检查地图是否正常：`ros2 topic echo /map --once`
- 必要时停止导航服务或终端程序，将机器人放回建图原点后重新启动。

## 9. 常见故障排查

### 9.1 地图不显示

现象：

- RViz 中没有 2D 地图。
- APP 地图空白。

检查：

```bash
ros2 node list | grep map_server
ros2 lifecycle get /map_server
ros2 topic echo /map --once
```

处理：

- 如果 `map_server` 未运行，重新启动导航系统。
- 如果生命周期不是 `active`，检查 lifecycle manager。
- 检查地图文件是否存在：

```bash
ls -lh /home/ubuntu/humanoid_ws/src/humanoid_navigation2/maps/hall.yaml
ls -lh /home/ubuntu/humanoid_ws/src/humanoid_navigation2/maps/hall.pgm
```

### 9.2 TF 缺失

现象：

- RViz 报 `No transform`。
- Nav2 无法启动。
- 机器人模型不在地图上。

检查：

```bash
ros2 run tf2_tools view_frames
ros2 run tf2_ros tf2_echo map odom
ros2 run tf2_ros tf2_echo odom base_footprint
```

处理：

- 检查 `fast_lio_node` 是否发布 `camera_init -> body`。
- 检查静态 TF 节点是否启动。
- 检查定位是否成功发布 `map -> odom`。

### 9.3 定位失败或机器人位置错误

现象：

- 机器人在 RViz 中位置明显不对。
- 点云与地图墙体不重合。
- `wait_for_tf` 一直等待。

检查：

```bash
ros2 topic hz /robot_realpose
ros2 topic echo /robot_realpose --once
ros2 run tf2_ros tf2_echo map odom
```

处理：

- 等待启动阶段 bootstrap 自动重定位完成。
- 如果仍失败，用 RViz `2D Pose Estimate` 设置初始位姿。
- 或 APP 发送 `initial_pose`。
- 确认机器人实际所在环境与当前 `hall` 地图一致。

### 9.4 导航不动

现象：

- APP 已点击开始导航，但机器人不走。

检查：

```bash
ros2 topic echo /navigation/status
ros2 topic echo /goal_pose
ros2 topic echo /cmd_vel
ros2 lifecycle get /bt_navigator
```

判断：

- `/cmd_vel` 没有数据：Nav2 没有规划或没有控制输出。
- `/cmd_vel` 有数据但机器人不走：底层 WebSocket 或机器人 Walk 模式异常。

处理：

- 检查目标点是否在障碍物或墙上。
- 检查 local costmap 是否被障碍挡住。
- 检查机器人底层状态是否为 `Walk`。
- 检查 `websocket_client_node` 是否连接本体。

### 9.5 路径规划失败

现象：

- APP 显示导航失败。
- RViz 没有全局路径。

检查：

```bash
ros2 topic echo /plan
ros2 topic echo /navigation/acknowledgments
```

处理：

- 重新选择离墙更远的目标点。
- 检查目标点附近是否是障碍区。
- 检查地图是否加载正确。
- 检查 global costmap 是否有异常障碍。

### 9.6 local costmap 有障碍残影

检查：

```bash
ros2 topic hz /airy_points_filtered
ros2 topic echo /tf_static --once
```

处理：

- 确认 `periodic_clearing_publisher` 和 `periodic_clearing_3d_publisher` 在运行。
- 检查 `clearing_lidar` TF。
- 检查点云滤波高度参数。

### 9.7 APP 连接不上

检查：

```bash
ros2 node list | grep websocket
```

处理：

- 确认 ROS 主机 IP。
- 确认 APP 连接端口和 WebSocket 地址。
- 确认电脑和 APP 在同一网络。
- 重新启动 WebSocket：

```bash
ros2 launch humanoid_websocket websocket_server.launch.py
```

### 9.8 APP 有连接但没有数据

检查：

```bash
ros2 topic echo /integration/push_messages
ros2 topic echo /websocket/data_subscriptions
```

处理：

- 确认 APP 已发送订阅请求。
- 确认订阅的数据类型正确，例如 `robot_pose`、`navigation_status`、`robot_speed`。
- 检查数据源是否存在，例如 `/robot_realpose`、`/navigation/status`、`/odom`。

### 9.9 表情控制无响应

检查：

```bash
ros2 node list | grep facial
ros2 topic pub --once /robot/facial_raw_cmd std_msgs/msg/String "{data: 'idle'}"
```

处理：

- 检查 `/dev/ttyUSB0` 是否存在。
- 检查表情模块 USB 是否插好。
- 检查串口权限。

### 9.10 动作执行后不能继续导航

现象：

- 执行上半身动作后，机器人暂时不能响应行走。

原因：

- 机器人执行动作时会切换到底层动作模式。
- 动作完成后需要切回 `Walk`。

处理：

- APP 必须订阅 `action_result`。
- 等待 `control_ready_for_navigation: true` 后再继续下发导航。
- 如果超时，检查 `/robot/action_result` 和底层状态。

### 13.1 一键启动脚本位置

```bash
#!/bin/bash
set -euo pipefail

WORKSPACE=/home/ubuntu/humanoid_ws
LOG_FILE="$WORKSPACE/debug_output.txt"

: > "$LOG_FILE"
exec > >(tee -a "$LOG_FILE") 2>&1

echo "Starting Humanoid Navigation at $(date)"

  echo "ERROR: /opt/ros/jazzy/setup.bash not found"
  exit 1

  echo "ERROR: $WORKSPACE/install/setup.bash not found. Run colcon build first."
  exit 1
fi

source /opt/ros/jazzy/setup.bash
source "$WORKSPACE/install/setup.bash"

python3 - <<'PY'
import importlib.metadata as metadata

required = ("humanoid-navigation", "humanoid-websocket")
missing = []
for package_name in required:
    try:
        metadata.distribution(package_name)
    except metadata.PackageNotFoundError:
        missing.append(package_name)

if missing:
    raise SystemExit(
        "ERROR: missing Python package metadata after sourcing install/setup.bash: "
        + ", ".join(missing)
    )
PY

echo "ROS environment loaded from $WORKSPACE/install/setup.bash"

ros2 launch humanoid_bringup robot_real.launch.py use_sim_time:=false
```

1. 进入工作空间 `/home/ubuntu/humanoid_ws`。
2. 清空并重新写入本次日志 `/home/ubuntu/humanoid_ws/debug_output.txt`。
3. 检查 ROS 2 Jazzy 环境文件是否存在。
4. 检查工作空间是否已经编译。
5. 加载 ROS 2 和工作空间环境。

### 13.2 systemd 服务名称

当前系统中已经存在导航服务文件：

```text
/etc/systemd/system/humanoid_nav.service
```

服务名称是：

```text
humanoid_nav.service
```

服务文件内容如下：

```ini
[Unit]
Description=Humanoid Robot Navigation Service
After=network.target

[Service]
Type=simple
User=ubuntu
ExecStart=/bin/bash /home/ubuntu/humanoid_ws/start_navigation.sh
WorkingDirectory=/home/ubuntu/humanoid_ws
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

含义说明：

- `User=ubuntu`：服务使用 `ubuntu` 用户运行。
- `ExecStart=/bin/bash /home/ubuntu/humanoid_ws/start_navigation.sh`：服务启动时运行一键脚本。
- `WorkingDirectory=/home/ubuntu/humanoid_ws`：工作目录为导航工作空间。
- `Restart=on-failure`：如果程序异常退出，systemd 会自动重启。
- `WantedBy=multi-user.target`：允许设置为开机自启。

注意：手动执行 `./start_navigation.sh` 时，它只是一个终端进程，没有 systemd 服务名称。只有通过 `systemctl start humanoid_nav.service` 或开机自启启动时，才由 `humanoid_nav.service` 管理。


看到 `disabled` 即表示下次开机不会自动启动。

### 13.6 自启后如何关闭导航系统

如果机器人开机后导航系统自动启动，后续不需要去找终端窗口，直接使用 systemd 命令停止：

```bash
sudo systemctl stop humanoid_nav.service
```

停止后确认：

```bash
sudo systemctl status humanoid_nav.service
```

如果状态中显示 `inactive`，说明导航系统已经停止。

如果只是临时停止，本次关机前不会再自动启动；但只要服务仍然是 `enabled`，下次开机仍会自动启动。

如果希望以后开机都不自动启动，执行：

```bash
sudo systemctl disable --now humanoid_nav.service
```

停止后建议清理 ROS 2 daemon 缓存并确认节点列表：

```bash
ros2 daemon stop
ros2 node list --no-daemon
```

如果现场同时启用了导航漂移在线监控页面，还需要停止对应服务：

```bash
sudo systemctl stop nav-drift-live-56781.service nav-drift-static-56780.service
ros2 daemon stop
ros2 node list --no-daemon
```

### 13.7 修改服务文件后生效

如果修改了 `/etc/systemd/system/humanoid_nav.service`，需要执行：

```bash
sudo systemctl daemon-reload
sudo systemctl restart humanoid_nav.service
```

如果只是修改了 `/home/ubuntu/humanoid_ws/start_navigation.sh`，通常不需要 `daemon-reload`，直接重启服务即可：

```bash
sudo systemctl restart humanoid_nav.service
```

### 13.8 与 WebSocket 单独服务的关系

当前系统中还存在一个单独的 WebSocket 服务文件：

```text
/etc/systemd/system/humanoid_websocket.service
```

服务名称是：

```text
humanoid_websocket.service
```

它只启动：

```bash
/home/ubuntu/humanoid_ws/start_websocket.sh
```

正式导航系统 `humanoid_nav.service` 已经会通过 `robot_real.launch.py` 启动 WebSocket 相关节点。一般客户现场只需要管理 `humanoid_nav.service`。除非只想单独调试 APP 通信，否则不要同时重复启动 `humanoid_websocket.service`，避免端口或节点重复。

### 13.9 推荐客户现场使用方式

日常自动运行：

```bash
sudo systemctl enable --now humanoid_nav.service
```

之后每次开机前，将机器人放回建图原点附近；开机后等待约 1 分钟，再用 APP 操作导航。

临时停机调试：

```bash
sudo systemctl stop humanoid_nav.service
```

调试完成后重新启动：

```bash
sudo systemctl start humanoid_nav.service
```

永久取消自动运行：

```bash
sudo systemctl disable --now humanoid_nav.service
```
